# 회고 인터뷰어 (interviewer)

- 팀: 수집팀 (capture)
- LLM 사용: 예. 호출 실패나 키 없음 시 규칙 모드로 대체한다.
- 앞뒤 에이전트: record: privacy-guard → 본인 → card-writer

## 하는 일

기록에서 판단 이유·금지 행동·점장 호출 기준 중 빠진 내용을 찾는다.
직원이 짧게 답할 수 있는 질문만 되묻는다.

## 입력 / 출력

- 입력 `raw`: 개인정보를 가린 기록. 예: `쿠폰을 다시 스캔했어요`.
- 입력 `answered`: 되묻기 답을 받았는지 여부. 예: `false`.
- 출력 `followups`: 되묻기 질문 목록. 예: `["다시 스캔한 이유는 무엇인가요?"]`.
- 출력 `summary`: 질문 개수 요약. 예: `빠진 내용을 1개 되묻습니다`.

## 판단 규칙

1. 되묻기는 한 번에 0~2개로 제한한다.
2. 이미 answered가 true이면 추가 질문을 만들지 않는다.
3. 이유·금지·호출 기준 중 기록에 없는 항목을 묻는다.
4. 규칙 모드는 판단 이유와 금지 행동을 먼저 묻고, 자리가 남으면 호출 기준을 묻는다.
5. 직원이 말하지 않은 이유를 질문의 전제로 넣지 않는다.

## 하지 않는 일

LLM은 누락된 맥락을 읽고 질문을 만든다. 직원 대신 답을 채우지 않는다.
질문 수 제한과 답변 후 생략은 규칙이 맡는다.

## 실패하면

LLM 호출에 실패하면 같은 질문 목록 형식으로 규칙 결과를 낸다.
화면에는 규칙 모드로 표시한다. 별도 인터뷰 게이트는 없다.
뒤의 card-gate 실패 시 막힌 표현을 표시하고 작성자에게 돌려보내며 승인 대기로 저장한다.

## 근거 이론

참고 노트 3절은 사건에서 판단 이유를 꺼내는 일을 SECI 표출화로 설명한다.
회고를 행동 목록에서 끝내지 않고 이유까지 묻는 설계 근거다.
결정적 사건 기법은 노트의 상황·행동·결과·이유 수집 틀과 연결된다.

근거 범위: 참고 노트 「06_선정아이디어_매장위키」의 3~5절.
이론은 역할의 설계 근거다. 이 하네스의 성능 검증 결과는 아니다.
