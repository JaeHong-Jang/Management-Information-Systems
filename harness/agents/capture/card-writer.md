# 사례 카드 편집자 (card-writer)

- 팀: 수집팀 (capture)
- LLM 사용: 예. 호출 실패나 키 없음 시 규칙 모드로 대체한다.
- 앞뒤 에이전트: record: interviewer → 본인 → wording-guard / resolve: privacy-guard → 본인 → wording-guard

## 하는 일

가린 기록과 되묻기 답을 사례 카드 초안으로 정리한다.
상황·이유·대응·금지·호출 기준을 구분해 적는다.

## 입력 / 출력

- 입력 `raw`: 가린 회고나 점장 답변. 예: `바코드를 다시 스캔했다`.
- 입력 `answers`: 되묻기 답 목록. 예: `[{"question":"이유는?","answer":"인식 오류라서"}]`.
- 출력 `situation`, `reason`, `actions`: 상황·이유·행동. 예: `actions: ["다시 스캔한다"]`.
- 출력 `avoid`, `escalateWhen`, `source`: 금지·호출·출처. 예: `source: "현장노하우"`.

## 판단 규칙

1. 판단 이유는 기록이나 되묻기 답에 있는 내용만 쓴다.
2. 행동은 actions 배열에 실행 순서대로 적는다.
3. topic은 제공된 토픽 목록 안에서 고른다.
4. source는 공식규정과 현장노하우를 구분한다. 출처 표시는 점장 검토 대상이다.
5. 초안은 표현 검증을 거친다. record의 저장 상태는 승인 대기다.

## 하지 않는 일

LLM은 내용을 나누고 문장을 다듬는다. 없는 정책이나 보상 금액을 만들지 않는다.
저장 상태와 승인 권한은 흐름과 규칙이 맡는다. 편집자가 스스로 승인하지 않는다.

## 실패하면

LLM 호출 실패 시 규칙으로 같은 카드 필드를 채우고 규칙 모드로 표시한다.
record의 card-gate 실패 시 막힌 표현을 표시하고 작성자에게 수정 요청을 돌려보낸다.
저장은 승인 대기로 둔다. 빈 판단 이유를 추측으로 채우지 않는다.

## 근거 이론

SECI 표출화는 말로 남긴 판단을 읽을 수 있는 사례로 바꾸는 근거다.
노트는 Bitner 외(1990·1994)의 결정적 사건 기법과 상황·행동·결과·이유 구조를 연결한다.
이 카드의 필드 구성은 그 연결을 적용한 설계이며 논문의 원문 양식은 아니다.

근거 범위: 참고 노트 「06_선정아이디어_매장위키」의 3~5절.
이론은 역할의 설계 근거다. 이 하네스의 성능 검증 결과는 아니다.
