# 개인정보 가드 (privacy-guard)

- 팀: 수집팀 (capture)
- LLM 사용: 아니요. 규칙으로 실행한다.
- 앞뒤 에이전트: record: orchestrator → 본인 → interviewer / resolve: orchestrator → 본인 → card-writer

## 하는 일

직원 기록에서 정책 파일의 개인정보 패턴을 찾는다.
일치한 부분을 가리고 치환 횟수를 남긴다.

## 입력 / 출력

- 입력 `raw`: 직원 원문. 예: `010-1234-5678로 연락했어요`.
- 입력 `pii`: 적용할 정책 목록. 예: `phone` 규칙.
- 출력 `text`: 가린 기록. 예: `[전화번호]로 연락했어요`.
- 출력 `masked`: 치환 횟수. 예: `1`.

## 판단 규칙

1. 전화번호는 pii의 phone 정규식으로 찾아 [전화번호]로 바꾼다.
2. 16자리 카드번호 패턴은 [카드번호]로 바꾼다.
3. customer-name 패턴에 맞는 고객 실명은 [고객]으로 바꾼다.
4. 뒤 에이전트에는 가린 text를 넘긴다. 원문을 요약에 다시 적지 않는다.
5. masked가 0이어도 개인정보가 전혀 없다고 단정하지 않는다. 패턴 밖 표현은 놓칠 수 있다.

## 하지 않는 일

LLM으로 사람 이름을 추정하지 않는다. 정책 정규식이 치환을 맡는다.
전화번호 주인을 찾거나 가린 값을 복원하지 않는다.

## 실패하면

개인정보 치환에는 별도 게이트 onFail이 없다.
치환을 수행하지 못하면 원문을 다음 작성 단계로 넘기지 않는다.
뒤의 card-gate가 실패하면 표현을 표시해 돌려보내고 승인 대기로 저장한다.

## 근거 이론

Zhang, Wang & Zhang(2025)은 AI 인식과 암묵지 공유 감소의 관계를 다뤘다.
참고 노트 5절은 기여자 보호 설계에 개인정보 마스킹을 포함한다.
마스킹은 이 설계의 일부다. 논문이 마스킹의 효과를 검증했다는 뜻은 아니다.

근거 범위: 참고 노트 「06_선정아이디어_매장위키」의 3~5절.
