# 검색 사서 (librarian)

- 팀: 답변팀 (answer)
- LLM 사용: 아니요. 규칙으로 실행한다.
- 앞뒤 에이전트: ask: orchestrator → 본인 → coach

## 하는 일

승인된 사례 카드에서 질문과 가까운 사례를 찾는다.
한국어 2-gram BM25 점수로 후보를 정렬한다.

## 입력 / 출력

- 입력 `question`: 신입 질문. 예: `쿠폰이 인식되지 않아요`.
- 입력 `cards`: 승인 카드 목록. 예: `[{id: "C003", status: "approved", ...}]`.
- 출력 `card`: 검색 후보 카드. 예: `id: "C003"`.
- 출력 `score`, `coverage`: 검색 점수와 질문 일치 비율. 예: `4.2`, `0.4`.

## 판단 규칙

1. 검색 대상은 status가 approved인 카드다.
2. 질문과 문서의 한국어 2-gram을 비교한다.
3. BM25 점수가 0보다 큰 후보를 점수 내림차순으로 넘긴다.
4. score는 검색 순위용 값이다. 답의 정확도 확률로 읽지 않는다.
5. 후보가 0개이면 빈 목록을 넘긴다. 승인 대기 카드로 메우지 않는다.

## 하지 않는 일

LLM을 호출하지 않는다. 검색 점수와 정렬은 규칙이 맡는다.
후보를 찾았다는 이유로 답변 가능 여부나 환불 허용 여부를 결정하지 않는다.

## 실패하면

검색 결과가 없으면 현장 코치가 근거 없음으로 처리할 수 있게 빈 목록을 넘긴다.
별도 검색 게이트 onFail은 없다.
answer-gate 실패 시 근거 없는 문장을 빼고 다시 확인하며, 남는 문장이 없으면 점장에게 넘긴다.

## 근거 이론

Aamodt & Plaza(1994)의 4R 중 Retrieve에 해당한다.
새 질문을 과거 사례와 연결하는 역할이다.
BM25는 이 서비스의 검색 방식이다. 4R 이론이 정한 검색 알고리즘은 아니다.

근거 범위: 참고 노트 「06_선정아이디어_매장위키」의 3~5절.
이론은 역할의 설계 근거다. 이 하네스의 성능 검증 결과는 아니다.

## 신입이 체감하는 것

비슷한 일을 겪은 선배의 승인 사례부터 찾는다.
