# 점장 연결 (escalator)

- 팀: 답변팀 (answer)
- LLM 사용: 아니요. 규칙으로 실행한다.
- 앞뒤 에이전트: ask: wording-guard → 본인 → 흐름 종료

## 하는 일

근거 부족과 검증 결과를 보고 점장 연결 여부를 정한다.
카드의 호출 기준에 해당할 수 있으면 그 기준을 알린다.

## 입력 / 출력

- 입력 `question`, `ans`: 질문과 검증된 답. 예: `ans.needsManager: true`.
- 입력 `gatePassed`, `cards`: 게이트 통과 여부와 카드. 예: `false`, `[{id: "C003", ...}]`.
- 출력 `escalate`: 점장에게 넘길지 여부. 예: `true`.
- 출력 `note`: 연결 사유나 호출 안내. 예: `근거 카드 없음`.

## 판단 규칙

1. needsManager가 true이거나 confidence가 none이면 점장에게 넘긴다.
2. 게이트 실패 뒤 유효한 인용도 없으면 점장에게 넘긴다.
3. 호출 기준은 인용한 카드의 escalateWhen에서 읽는다.
4. 현재 규칙은 질문과 호출 기준의 containment가 0.35 이상이면 호출 가능성을 안내한다. 이 조건만으로 자동 연결하지는 않는다.
5. 노트의 큰 환불·안전·폭언 사례는 위험 예시다. 공통 금액 기준을 새로 정하지 않는다.

## 하지 않는 일

LLM을 호출하지 않는다. 연결 여부와 사유 표시는 규칙이 맡는다.
점장 대신 보상을 승인하거나 아직 오지 않은 점장 답을 만들지 않는다.

## 실패하면

answer-gate의 onFail에 따라 근거 없는 문장을 빼고 다시 확인한다.
남는 문장이 없으면 점장에게 넘긴다.
점장 답변은 resolve 흐름에서 가림·카드 편집·표현 검증·종합을 거쳐 재축적한다.

## 근거 이론

Aamodt & Plaza(1994)의 4R 중 Revise와 Retain으로 넘어가는 연결점이다.
참고 노트 5절은 위험한 예외를 매니저에게 넘기고 결정을 다시 위키에 남기도록 제안한다.
지금 답하지 못한 질문도 다음에 쓸 사례가 되도록 하는 설계다.

근거 범위: 참고 노트 「06_선정아이디어_매장위키」의 3~5절.
이론은 역할의 설계 근거다. 이 하네스의 성능 검증 결과는 아니다.

## 신입이 체감하는 것

혼자 판단하기 어려운 질문을 점장에게 넘길 수 있다.
