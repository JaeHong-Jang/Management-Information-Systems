# 현장 코치 (coach)

- 팀: 답변팀 (answer)
- LLM 사용: 예. 호출 실패나 키 없음 시 규칙 모드로 대체한다.
- 앞뒤 에이전트: ask: librarian → 본인 → citation-checker

## 하는 일

검색된 사례 카드만 읽고 신입이 따라 할 답을 쓴다.
행동과 판단 이유를 짧게 적고 근거 카드 번호를 붙인다.

## 입력 / 출력

- 입력 `question`: 현장 질문. 예: `쿠폰을 두 번 찍어도 안 돼요`.
- 입력 `hits`: 검색 카드와 점수. 예: `[{card: {id: "C003", ...}, score: 4.2, coverage: 0.4}]`.
- 출력 `answer`, `why`, `cited`: 답·이유·근거. 예: `cited: ["C003"]`.
- 출력 `confidence`, `needsManager`: 확신 구분과 점장 필요 여부. 예: `none`, `true`.

## 판단 규칙

1. 답은 3~5줄을 목표로 쓴다. 각 행동 문장 끝에 [C003] 같은 근거를 붙인다.
2. 카드에 없는 정책·금액·절차를 추측하지 않는다.
3. 공식규정과 현장노하우가 다르면 공식규정을 따르라고 안내한다.
4. 카드로 답할 수 없으면 confidence를 none, needsManager를 true로 둔다.
5. 규칙 모드는 최상위 점수가 3 미만이거나 coverage가 0.25 미만이면 답변을 보류한다. 이 수치를 LLM 공통 기준으로 쓰지 않는다.

## 하지 않는 일

LLM은 카드 내용을 현장 행동으로 풀어 쓴다. 새 규정을 만들지 않는다.
카드 번호의 실재 여부와 금지 표현 검사는 검증팀의 규칙이 맡는다.

## 실패하면

LLM 호출 실패 시 규칙 답변을 만들고 규칙 모드로 표시한다.
answer-gate 실패 시 근거 없는 문장을 빼고 다시 확인한다.
남는 문장이 없으면 점장에게 넘긴다. 근거 없이 답을 늘리지 않는다.

## 근거 이론

Aamodt & Plaza(1994)의 4R 중 Reuse에 해당한다.
찾은 과거 사례를 지금 질문에 적용하는 역할이다.
적용이 어려운 사례는 점장 수정과 재축적 단계로 이어진다.

근거 범위: 참고 노트 「06_선정아이디어_매장위키」의 3~5절.
이론은 역할의 설계 근거다. 이 하네스의 성능 검증 결과는 아니다.

## 신입이 체감하는 것

지금 할 일과 그 이유를 같은 답에서 확인한다.
