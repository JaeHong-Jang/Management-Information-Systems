# 근거 검증 (citation-checker)

- 팀: 검증팀 (verify)
- LLM 사용: 아니요. 규칙으로 실행한다.
- 앞뒤 에이전트: ask: coach → 본인 → policy-checker

## 하는 일

답에 붙은 카드 번호가 실제 승인 카드인지 확인한다.
검색한 카드인지도 확인하고 근거 표시가 빠진 부분을 찾는다.

## 입력 / 출력

- 입력 `ans`: 코치 답. 예: `answer: "바코드를 확인하세요 [C003]"`.
- 입력 `approvedIds`, `retrievedIds`: 승인·검색 카드 집합. 예: 각각 `{"C003"}`.
- 출력 `answer`: 검사를 반영한 답. 예: `cited: ["C003"]`.
- 출력 `problems`: 근거 문제 목록. 예: `["검색되지 않은 카드 인용: C999"]`.

## 판단 규칙

1. [C003]처럼 C와 세 자리 이상 숫자로 된 카드 번호를 찾는다.
2. 본문과 cited의 카드 번호가 승인 집합에 없으면 문제로 기록한다.
3. 승인 카드라도 검색 집합에 없으면 문제로 기록한다.
4. 근거 표시가 없는 행동 문장은 answer-gate에서 제거 후 재확인할 대상이다.
5. 번호의 존재 검사는 문장의 의미가 카드와 같다는 보증이 아니다. 의미 검증을 마쳤다고 표시하지 않는다.

## 하지 않는 일

LLM을 호출하지 않는다. 카드 집합 대조와 표식 검사는 규칙이 맡는다.
번호가 없는 문장에 비슷해 보이는 카드 번호를 임의로 붙이지 않는다.

## 실패하면

answer-gate 실패 시 근거 없는 문장을 빼고 다시 확인한다.
남는 문장이 없으면 점장에게 넘긴다.
없는 카드 번호를 새 카드 생성으로 맞추지 않는다.

## 근거 이론

Aamodt & Plaza(1994)의 4R 중 Reuse를 과거 사례에 묶어 두는 검사다.
새 답이 어느 사례를 재사용했는지 추적하려는 설계다.
카드 번호 검사 방식 자체가 해당 논문에서 검증된 것은 아니다.

근거 범위: 참고 노트 「06_선정아이디어_매장위키」의 3~5절.
이론은 역할의 설계 근거다. 이 하네스의 성능 검증 결과는 아니다.

## 신입이 체감하는 것

답에 붙은 카드 번호를 보고 실제 승인 사례를 찾아볼 수 있다.
