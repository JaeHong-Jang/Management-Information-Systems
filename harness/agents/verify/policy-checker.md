# 규정 우선 검증 (policy-checker)

- 팀: 검증팀 (verify)
- LLM 사용: 아니요. 규칙으로 실행한다.
- 앞뒤 에이전트: ask: citation-checker → 본인 → wording-guard

## 하는 일

인용 카드에서 공식규정과 현장노하우가 함께 쓰였는지 본다.
같은 토픽에서 두 출처가 섞이면 공식규정 우선 안내를 확인한다.

## 입력 / 출력

- 입력 `ans`: 인용 검사를 거친 답. 예: `cited: ["C006", "C007"]`.
- 입력 `cards`: 승인 카드 목록. 예: `source: "공식규정", topic: "교환·환불"`.
- 출력 `answer`: 우선 안내를 반영한 답. 예: `공식규정을 따르세요. [C006]`.
- 출력 `problems`: 안내 누락 목록. 예: `["규정 우선 안내 누락"]`.

## 판단 규칙

1. 검사는 ans.cited에 든 승인 카드를 대상으로 한다.
2. 같은 토픽에 서로 다른 source가 있으면 혼합 인용으로 본다.
3. 혼합 인용인데 답에 공식규정 안내가 없으면 누락으로 기록하고 안내를 덧붙인다.
4. 같은 토픽의 혼합 인용은 보수적인 확인 조건이다. 실제 모순을 뜻한다고 단정하지 않는다.
5. 공식규정 카드가 없으면 현장노하우를 공식규정으로 바꾸지 않는다.

## 하지 않는 일

LLM을 호출하지 않는다. 토픽·출처 비교와 안내 누락 검사는 규칙이 맡는다.
법률 해석이나 본사 규정 개정을 하지 않는다.

## 실패하면

안내 누락도 answer-gate 문제로 남긴다. 안내 추가만으로 통과를 선언하지 않는다.
게이트 실패 시 근거 없는 문장을 빼고 다시 확인한다.
남는 문장이 없으면 점장에게 넘긴다.

## 근거 이론

Aamodt & Plaza(1994)의 4R은 과거 사례의 재사용과 수정을 구분한다.
다른 조건의 현장 관행을 그대로 적용하지 않도록 확인하는 설계에 이 구분을 쓴다.
공식규정 우선순위는 이 서비스의 정책이다. 4R이 정한 규정 체계는 아니다.

근거 범위: 참고 노트 「06_선정아이디어_매장위키」의 3~5절.
이론은 역할의 설계 근거다. 이 하네스의 성능 검증 결과는 아니다.

## 신입이 체감하는 것

선배의 관행과 공식규정이 함께 나와도 무엇을 따라야 할지 안다.
