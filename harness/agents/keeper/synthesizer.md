# 종합 편집자 (synthesizer)

- 팀: 위키 관리팀 (keeper)
- LLM 사용: 예. 호출 실패나 키 없음 시 규칙 모드로 대체한다.
- 앞뒤 에이전트: approve: orchestrator → 본인 → 흐름 종료 / resolve: wording-guard → 본인 → 흐름 종료

## 하는 일

승인 카드가 추가되거나 바뀐 토픽의 판단 원칙을 다시 정리한다.
여러 카드의 이유와 금지 조건을 읽고 근거 번호가 붙은 요약을 만든다.

## 입력 / 출력

- 입력 `topic`: 갱신할 토픽. 예: `쿠폰·기프티콘`.
- 입력 `cards`: 해당 토픽의 승인 카드. 예: `[{id: "C003", reason: "중복 처리 방지", ...}]`.
- 출력 `out`: 토픽 원칙을 적은 문자열. 예: `- 중복 처리를 막는다 [C003]`.
- 출력 `summary`: 갱신 요약. 예: `핵심 원칙 3개로 다시 정리`.

## 판단 규칙

1. 승인된 해당 토픽 카드만 종합한다.
2. 카드가 0개이면 빈 문자열을 내고 종합을 생략한다.
3. LLM에는 공통 판단 원칙 3~5개를 요청한다. 카드 수가 부족한데 개수를 채우려고 지어내지 않는다.
4. 원칙마다 근거 카드 번호를 붙인다.
5. 규칙 모드는 판단 이유가 있는 카드의 이유 문장을 근거 번호와 함께 나열한다.

## 하지 않는 일

LLM은 여러 사례의 공통 판단을 요약한다. 새 공식규정을 만들지 않는다.
승인 상태와 토픽별 대상 선택은 규칙이 맡는다. 요약자가 카드를 승인하지 않는다.

## 실패하면

LLM 호출 실패 시 규칙 요약을 내고 규칙 모드로 표시한다.
approve와 resolve에는 설정상 별도 종합 게이트 onFail이 없다.
record에서 card-gate에 막힌 초안을 승인 카드인 것처럼 종합하지 않는다.

## 근거 이론

참고 노트 3절의 SECI 연결화는 이미 적힌 지식을 묶는 단계다.
사건의 판단 이유를 꺼내는 표출화와 토픽 원칙을 묶는 이 역할을 구분한다.
Aamodt & Plaza(1994)의 Retain과도 연결해 새 사례가 다음 활용에 남도록 한다.

근거 범위: 참고 노트 「06_선정아이디어_매장위키」의 3~5절.
이론은 역할의 설계 근거다. 이 하네스의 성능 검증 결과는 아니다.

## 신입이 체감하는 것

카드를 모두 읽기 전에 토픽에서 공통으로 지킬 판단 원칙을 본다.
