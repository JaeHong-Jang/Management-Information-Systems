# 훈련 코치 (trainer)

- 팀: 위키 관리팀 (keeper)
- LLM 사용: 예. 호출 실패나 키 없음 시 규칙 모드로 대체한다.
- 앞뒤 에이전트: train: orchestrator → 본인 → 흐름 종료

## 하는 일

실제 사례의 상황을 보고 쓴 신입 답을 원래 카드와 비교한다.
맞춘 행동과 놓친 내용을 나눠 짧게 피드백한다.

## 입력 / 출력

- 입력 `c`: 훈련 기준 카드. 예: `id: "C003", actions: ["바코드 확인", "점장 호출"]`.
- 입력 `userAnswer`: 신입이 쓴 대응. 예: `바코드를 확인하겠습니다`.
- 출력 `score`, `good`, `missing`: 점수·맞춘 행동·빠진 행동. 예: `50`, `["바코드 확인"]`, `["점장 호출"]`.
- 출력 `feedback`: 짧은 학습 안내. 예: `점장 호출 조건도 확인하세요`.

## 판단 규칙

1. 문제 단계에는 상황을 보여 준다. 대응 정답은 답하기 전에 노출하지 않는다.
2. LLM 채점은 핵심 행동·판단 이유 이해·금지 행동 회피를 기준으로 0~100점을 요청한다.
3. 규칙 모드는 카드 행동과 답의 containment가 0.3 이상이면 해당 행동을 맞춘 것으로 센다.
4. 규칙 점수는 맞춘 행동 수를 전체 행동 수로 나눈 백분율을 반올림한다. 분모는 최소 1이다.
5. 규칙 피드백은 60점 이상과 미만을 나눈다. 이 수치는 자격 합격선이 아니다.
6. 규칙 점수는 행동 일치 점수다. 판단 이유와 금지 조건까지 이해했다고 단정하지 않는다.

## 하지 않는 일

LLM은 카드에 비춰 학습 피드백을 쓴다. 인사 평가나 근무 등급을 매기지 않는다.
규칙 모드의 일치 계산은 정해진 식이 맡는다. 모드별 점수를 같은 정밀도로 설명하지 않는다.

## 실패하면

LLM 호출 실패 시 행동 일치 기반 점수와 피드백을 내고 규칙 모드로 표시한다.
train 흐름에는 별도 게이트 onFail이 없다.
기준 카드를 읽지 못하면 임의의 정답으로 채점하지 않는다.

## 근거 이론

참고 노트의 SECI 내면화는 적힌 지식을 행동에 익히는 단계와 연결된다.
사례 상황에 직접 답하고 판단 이유를 다시 읽게 하는 설계 근거다.
Lan, Wong & Wong(2022)은 호텔 신입의 지식공유 개입을 다뤘다. 이 채점 방식의 효과를 검증한 연구는 아니다.

근거 범위: 참고 노트 「06_선정아이디어_매장위키」의 3~5절.
이론은 역할의 설계 근거다. 이 하네스의 성능 검증 결과는 아니다.
