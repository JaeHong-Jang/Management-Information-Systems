# 위키 점검관 (linter)

- 팀: 위키 관리팀 (keeper)
- LLM 사용: 예. 호출 실패나 키 없음 시 규칙 모드로 대체한다.
- 앞뒤 에이전트: lint: orchestrator → 본인 → 흐름 종료

## 하는 일

카드와 질문의 관리 상태를 점검해 점장이 확인할 일을 만든다.
수치·날짜는 규칙으로 확인하고 문장 간 상충은 LLM이나 대체 규칙으로 찾는다.

## 입력 / 출력

- 입력 `cards`, `questions`: 카드와 질문 목록. 예: `status: "pending"`인 카드.
- 입력 `topics`, `today`: 토픽 목록과 매장 기준일. 예: `today: "2026-10-31"`.
- 출력 `issues`: 종류·카드 번호·설명. 예: `{kind: "만료", ids: ["C003"], detail: "만료일 경과"}`.
- 출력 `links`: 카드 관계 목록. 예: `{source: "C003", target: "C004", type: "duplicates"}`.

## 판단 규칙

1. expires가 기준일보다 이르면 만료다. 기준일부터 14일 이내이면 만료 임박이다.
2. uses가 3 이상이고 notHelpful가 helpful보다 크면 효과 낮음으로 표시한다.
3. 같은 토픽 카드의 제목·상황 유사도가 0.3을 넘으면 중복 후보로 표시한다.
4. 기타를 뺀 토픽의 승인 카드가 2개 미만이면 공백이다. 점장 답 대기 질문도 공백으로 모은다.
5. 판단 이유가 비었거나 pending 카드가 있으면 각각 이유 없음·승인 대기로 남긴다.
6. 상충 후보를 먼저 보여 준다. 후보 탐지는 점장의 최종 판단을 대신하지 않는다.

## 하지 않는 일

LLM은 서로 모순되는 지시를 찾는다. 만료일이나 도움 횟수를 추측하지 않는다.
날짜·횟수·유사도 검사는 규칙이 맡는다. 카드 삭제·병합·승인은 자동 실행하지 않는다.

## 실패하면

LLM 호출 실패 시 상충 탐지도 규칙으로 바꾸고 규칙 모드로 표시한다.
lint 흐름에는 별도 게이트 onFail이 없다.
검사하지 못한 부분을 문제없음으로 보고하지 않는다. 점검 결과는 점장 할 일로 남긴다.

## 근거 이론

Aamodt & Plaza(1994)의 Revise와 Retain을 지식 관리에 적용한다.
저장한 사례도 재사용 결과와 바뀐 조건에 맞춰 다시 살펴야 한다는 설계다.
14일·3회 같은 임계값은 구현 규칙이다. 논문에서 가져온 수치는 아니다.

근거 범위: 참고 노트 「06_선정아이디어_매장위키」의 3~5절.
이론은 역할의 설계 근거다. 이 하네스의 성능 검증 결과는 아니다.

## 신입이 체감하는 것

오래됐거나 서로 다른 안내를 점장이 다시 확인할 수 있다.
