# 근무 지도 설계 (Corevis·「지속 가능한 구조」 참고 고도화)

2026-11-02. 윤슬의 "알바가 바뀌어도 서비스가 같은 매장"을 근무 단위로 끝까지 가게 만든다. 참고: Corevis(말 한 줄 → 단계 지도, 단계마다 완료 기준, AI를 팀원처럼 배정, 승인, "이어서 해 줘"), jay.ai.daily의 5단계(판정 → 기억 → 실행 고리 → 스스로 고치기 → 업그레이드 점검).

## 무엇을 더하나

| 참고 | 윤슬에서 |
|---|---|
| 말 한 줄 → 단계 지도 | "마감하고 발주까지"라고 말하면 근무 설계자가 루틴(오픈 준비·마감·발주·행사 준비)을 골라 단계 지도를 만든다 |
| 단계마다 완료 기준 체크리스트 | 단계마다 판정표. 줄은 세 종류: 자료로 확인(시스템), 직접 체크(직원), 점장이 볼 것(사람만 정할 수 있는 것) |
| 일한 세션이 채점하지 않는다 | 판정관(검증팀, 규칙)이 줄마다 합격·불합격·모름과 근거를 낸다. 비어 있으면 합격이 아니라 모름. 3번 불합격이면 점장에게 |
| AI를 팀원처럼 배정 | 단계마다 담당: 에이전트(POS 정리원·발주 담당·수요 분석가·근무 설계자) 또는 역할(신입·숙련·점장) |
| 이어서 해 줘 · 기록은 파일에 | 근무 넘기기: 끝난 단계·지금 단계·남은 기준·막힌 것·볼 카드를 인계 메모로 남기고, 다음 사람은 지금 단계부터 잇는다. 근무 기록은 저장소에 남는다 |
| 같은 지적 두 번 → 규칙 | 같은 기준이 근무 두 번 이상에서 불합격이면 위키 점검관이 '반복 실수'로 점장 할 일에 올린다(카드로 남기라는 안내) |
| 합격한 것만 기억 | 근무 기록에는 판정 결과와 근거를 남기고, 위키 카드는 지금처럼 점장 승인만 쌓는다 |

## 자료

- 루틴 템플릿 `data/routines.json`: 루틴 → 묶음(레인) → 단계(담당, 근거 카드, 이동할 화면, 판정 줄).
- 판정 줄 `auto` 규칙: POS 반영(마지막 판매일이 어제 이후), 오늘 마감 실사, 재고 차이 없음, 주문서 모두 보냄, 도착 전 바닥 없음, 보정·소모량 결정, 행사 보정 있음, 점장 대기 질문 없음, 인계 메모 있음.
- 근무 `shifts`(저장소): 단계 상태(todo·passed·failed·waiting), 체크한 줄, 점장 확인한 줄, 판정 결과, 불합격 횟수, 불합격한 줄, 인계 메모, 기록.

## 하네스

- 근무 설계자(지휘팀, LLM, 규칙 대체: 루틴 키워드), 판정관(검증팀, 규칙).
- 흐름 `shift`(근무 지도 만들기·넘기기), `judge`(판정).

## 화면

현장 묶음 맨 위에 「근무 지도」. Corevis 배치: 위에 "오늘 할 일을 말해 보세요"와 예시, 가운데 묶음별 단계 카드(담당·판정 진행·근거 카드·상태), 오른쪽에 고른 단계의 판정표, 아래에 붙은 실행 바(지금 단계 · 누구 차례 · 판정 받기 · n/m · 근무 넘기기). 인계 메모는 지도 위에. 대시보드에 근무 한 줄, 에이전트 단계 지도에 근무 흐름 묶음.

## 리뷰 뒤 보탠 규칙

- 단계는 차례대로만 판정한다(지금 단계 = 아직 합격하지 않은 첫 단계).
- 3번 불합격한 단계는 점장만 다시 판정하고, 점장 손이 필요한 단계(점장이 볼 줄 남음·3번 불합격)는 '근무 대기'로 점장 할 일에 오른다.
- 날짜 줄은 판정하는 날이 아니라 근무의 영업일 기준이다. 자정 넘어 넣은 마감 실사도 그 근무 것으로 본다.
- 행사 보정은 이유 글이 아니라 기간이 겹치는지로 확인한다(AI가 이유를 자유롭게 써도 통과).
- 합격한 단계의 체크를 지우면 다시 판정 대기로 돌아간다.
- 루틴 키워드에서 흔한 말(시작·주문·단체)을 뺐다.

## 하지 않는 것

일정 예약 실행, 폰 지문 승인, 루틴 편집 화면. 루틴은 JSON으로 고친다.
