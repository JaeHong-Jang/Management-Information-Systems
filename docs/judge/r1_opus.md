## 1. 판정

**본선 진출 가능성: 중간 · 총점 68/100**

문제를 잘 골랐고, 근거가 붙은 답과 점장 답의 재축적이라는 지식 순환을 실제로 돌아가는 화면으로 보여 준다. 학생 출품작으로는 드물게 정직하고 완성도도 높다. 다만 핵심 주장인 "AI가 판단 이유를 되묻는다"가 실제 LLM으로 한 번도 시연되지 않았다. 스크린샷, 시연 기록, 테스트가 모두 규칙 모드다. 사업 근거(지불 의향, 가격, 점장 검수 부담)도 비어 있다.

## 3. 가장 치명적인 문제 3개

### 1) "AI 회고 인터뷰"가 실제 AI로 시연된 적이 없다
- **무엇이**: 스크린샷 11장 모두 상단에 `규칙 모드 (API 키 없음)`가 떠 있다. `docs/judge/demo_run.md` 제목도 "규칙 모드"다. 테스트도 규칙 모드다(`ARCHITECTURE.md` 검증 절). 규칙 모드의 인터뷰어는 "때문|이유|해서" 같은 단어가 없으면 미리 정해 둔 질문 3개 중 2개를 내보낸다. 종합 편집자는 카드 판단 이유의 첫 문장을 그대로 잘라 붙인다. 그래서 위키 화면의 '쿠폰·기프티콘 핵심 판단 원칙'은 "대부분은 다른 매장에서 스캔만 하고…"처럼 원칙이 아닌 문장이 됐다.
- **왜 치명적인가**: 기술 활용성 기준은 "AI를 썼다는 사실이 아니라 적절성과 구체성"을 본다. 이 작품의 차별점(SECI 표출화, 판단 이유를 끌어내는 질문)은 LLM 품질에 달려 있는데, 그 증거가 지금 0이다. 심사위원이 "그럼 정규식이 다 한 것 아니냐"고 물으면 답할 자료가 없다.
- **어떻게 고칠지**: API 키를 넣고 `/api/demo/play`를 다시 돌려 `docs/judge/demo_run.md`에 LLM 모드 기록을 따로 남긴다. 같은 숙련자 기록 5~10건을 놓고 규칙 모드와 LLM 모드의 되묻기 질문, 완성된 카드를 나란히 비교하는 표를 `docs/ARCHITECTURE.md` 검증 절에 추가한다. '에이전트 팀' 화면의 실행 기록 줄마다 `via: claude / rules`를 보이게 하고, LLM 모드 스크린샷(`record`의 2단계 'AI가 되묻기', `wiki`의 핵심 원칙)을 `docs/screenshots/`에 추가한다.

### 2) 만료되고 공식규정과 상충하는 카드가 신입 답의 근거로 그대로 나간다
- **무엇이**: `backend/src/store/db.ts`의 `approvedCards()`는 `status === 'approved'`만 거르고 만료일은 보지 않는다. 검색(`flows/index.ts` ask 흐름)과 근거 검증(`citationChecker`)도 만료를 확인하지 않는다. 실제로 `wiki` 스크린샷의 최근 변경 기록에는 "[Q003] 영수증 없이 환불해 달래요 → C006, C007"이 있다. 그런데 같은 시점 `manager` 화면의 점검관은 C007("단골 고객은 영수증 없어도 원두 교환 해줘도 됨", 현장노하우)을 **만료(2026-09-10)**, **효과 낮음**, **C006(공식규정)과 상충**으로 동시에 지적하고 있다. 질문하기 화면의 답에도 만료 표시가 없다(`frontend/src/features/ask/index.tsx`에 expires 참조 없음). 게다가 점장의 '갱신' 버튼은 내용 확인 없이 만료일만 120/180일 늘린다(`cardAction`의 renew 분기).
- **왜 치명적인가**: 이 작품의 신뢰 논리는 "근거가 붙은 답, 낡은 관행은 걸러냄"이다. 그런데 점검관이 문제라고 찍은 카드를 답변팀이 그대로 쓴다면, 위키 점검은 할 일 목록일 뿐 안전장치가 아니다. 환불처럼 정산·분쟁이 걸린 영역에서 실무자가 가장 먼저 지적할 부분이다. 정책 검증기가 "공식규정을 따르세요"를 덧붙여 일부 완화하지만, 만료된 관행 카드가 근거 목록에 함께 뜨는 것 자체가 문제다.
- **어떻게 고칠지**: ask 흐름에서 만료됐거나 상충으로 표시된 카드는 검색 대상에서 빼거나, 쓰더라도 `citationChecker`가 "만료된 근거"를 problem으로 올려 게이트를 막게 한다(`backend/src/agents/verify.ts`). 질문하기 답에는 근거 카드마다 출처(공식규정/현장노하우)와 만료 배지를 단다. '갱신'은 카드 내용을 보여 주고 "지금도 맞다" 확인을 받은 뒤 연장하도록 바꾼다(`frontend/src/features/manager`). 이 시나리오를 `backend/test/flows.test.ts`에 테스트로 추가한다.

### 3) 효과·사업 근거가 없는데, 지표 화면은 성과가 난 것처럼 보인다
- **무엇이**: `metrics` 화면 상단 카드는 "재사용된 횟수 101", "해결됐다고 답한 비율 100%", "판단 이유가 채워진 카드 100%"다. 101은 시드 데이터에 미리 넣은 uses 값의 합이다(`/api/metrics`의 totalReuse, 시드 카드 C001 uses 14 등). 100%는 피드백 몇 건(n 미표시)에서 나온 값이다. 설명문에 "시연 데이터라 실제 매장 효과를 뜻하지 않아요"라고 적긴 했지만, 큰 숫자 바로 옆에 n과 '시드'가 표시되지 않는다. 전략 문서가 약속한 기록·검수 시간 지표는 없고, 가격과 지불 의향도 없다.
- **왜 치명적인가**: 비즈니스 타당성 20점의 핵심 질문은 "점장이 돈을 내고, 바쁜 숙련자가 계속 기록할까"다. 지금 자료로는 이 질문에 "모른다"밖에 답할 수 없다. 학회가 비판해 온 디지털 그림자노동(직원에게 무급 기록을 떠넘기는 문제)을 피했다는 주장도 검수 시간을 재지 않으면 증명할 수 없다.
- **어떻게 고칠지**: (a) `frontend/src/features/metrics`의 상단 숫자에 "n=?"과 "시드 포함/제외" 토글을 붙이고, '기록 1건 평균 소요', '점장 검수 1건 평균 소요' 카드를 추가한다(실행 버스 이벤트 시간으로 계산 가능 [추론]). (b) 본선 전에 아는 카페 1~2곳의 점장·알바 5명 이상과 15분 인터뷰를 해서 예외 빈도, 반복 설명 횟수, 월 지불 의향을 받아 `docs/strategy/차별화_전략.md` 비즈니스 절에 넣는다. (c) 선정 노트의 월 19,900~29,900원 가설을 "가정"으로 표기해 제안서에 옮기고, 모두의매뉴얼(매장당 약 1.2만~1.8만 원)과 비교한다.
