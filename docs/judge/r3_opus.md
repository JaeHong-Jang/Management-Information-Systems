## 3. 가장 치명적인 문제 3개

1. **'AI 회고 인터뷰'가 세 라운드 동안 0회 실행됐다.**
   - 무엇이: `/api/state`의 `ai.mode=rules`이고, `llm_vs_rules.md`의 LLM 열은 6건 모두 '미실행'이다. 같은 표의 규칙 열에서 6건 중 5건이 '이유: (빈칸)'이다.
   - 왜: 공고문 2번 기준과 차별점의 핵심이 이 기능이다. 발표장에서 키를 넣고 시연했는데 처음 보는 출력이 나오면 위험하다.
   - 어떻게: `backend/scripts/compare_modes.ts`를 실제 키로 실행해 6건의 되묻기·카드·호출 비용·지연을 `docs/judge/llm_vs_rules.md`에 채운다. 실패 사례도 함께 싣는다. `docs/screenshots/record-step2-1440.png`를 LLM 모드 화면으로 1장 추가한다.
2. **안전 안전망이 단어 목록이고, 안전 답에 엉뚱한 사례가 붙는다.**
   - 무엇이: '칼', '베었', '숨쉬기 힘들', '경련', '부었', '행패', '쏟았'이 `alwaysEscalate`를 통과한다. 이 질문들은 일반 검색 답으로 흘러간다. 걸린 경우에도 `flows/index.ts`의 안전 분기는 검색 1순위 카드 줄 2개를 '참고할 매장 사례'로 붙인다. 데모 Q006 '욕설하며 위협'에는 C011(줄이 길 때 재촉)의 "'기다리게 해서 죄송합니다'로 시작한다"가 붙었다. '왜 이렇게 하나요'에도 대기 고객 설명이 나온다.
   - 왜: 2025년 학술대회 주제가 「안전한 정보와 지식」이었다. 신입에게 위협 상황에서 사과로 대응하라는 지시가 보이면 신뢰가 무너진다.
   - 어떻게: (a) `harness/policies/forbidden-phrases.json`에 흉기·출혈·호흡곤란·경련·부종·화상 위험·취객·스토킹 어휘를 보강하고, 바꿔 말한 질문 30개 회귀 세트를 `backend/test`에 추가한다. (b) 안전 분기에서는 카드의 `avoid`·`escalateWhen` 줄만 보이고, 처리 단계(`actions`)와 `why`는 빼거나 '안전' 태그 카드로 제한한다. (c) LLM 모드에서는 안전 분류를 이중으로 확인한다.
3. **사업·효과 근거 0건, 제출 증거와 현재 코드가 어긋난다.**
   - 무엇이: 지불 의향·검수 시간·반복 설명 시간이 하나도 없다. `docs/screenshots/overview-live-1440.png`·`agents-1440.png`는 수정 전 화면(개인별 질문 수, 영문 ID, 반복 점검 기록)이다. `ask-safety-1440.png`도 현재 `ask/index.tsx`와 다르다. `frontend/dist`(02:01)는 ask 수정(02:02)보다 이전 빌드다. `data/wiki/people.md`의 '개인별로 기록하지 않는다'는 `askerId` 저장 사실과 다르다.
   - 왜: 심사위원이 화면과 문서를 대조하면 '주장만 하고 확인하지 않았다'는 인상을 준다. 그동안 이 팀의 강점이었던 정직성 점수를 깎아 먹는다.
   - 어떻게: 프론트를 다시 빌드한 뒤 10개 화면을 모두 재캡처하고, 캡처 시각과 커밋을 `docs/judge/demo_run.md`에 적는다. `store/db.ts`의 위키 컴파일 문구를 '질문자 ID는 내 질문 다시 보기용으로만 저장, 개인별 집계 안 함'으로 고친다. 실제 카페 점주 3명 인터뷰(가격 가설 질문 포함)와 검수 1건 시간 측정을 `docs/strategy/차별화_전략.md` §3에 추가한다.

1. **"AI가 회고 인터뷰를 한다는데, 실제 AI 출력을 보여 줄 수 있습니까?"**

3. **"점주가 이걸 돈 내고 쓰겠습니까? 점장 검수에 시간이 얼마나 듭니까?"**

4. **"점장이 잘못 답하면 그게 그대로 신입의 근거가 되지 않습니까?"**
   금지 표현이 있으면 승인 대기로 막습니다. 만료·상충 카드는 근거에서 빠지고, 120~180일 뒤 만료되어 재검토 대상이 됩니다. 하지만 표현에 문제가 없는 잘못된 내용은 막지 못합니다. 계정이 없어 답한 사람이 실제 점장인지도 확인하지 못합니다.
