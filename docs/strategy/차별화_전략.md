# 이어받기 차별화 전략

이 문서는 출품작의 설계와 검증 계획이다. 기능 구현 여부와 현장 효과를 확인한 보고서는 아니다. 외부 사실은 저장소에 있는 자료만 인용했다. ‘부분검증’과 ‘미확인’은 원자료의 확인 수준을 유지했다. 시연용 사례와 실제 매장 기록은 화면에서도 구분한다.

## 1. 한 문장 정의

**이어받기는 선배의 예외 대응 이유와 점장의 답을 매장 위키에 쌓아, 신입도 근거를 보고 일하도록 돕는 AI 서비스다.**

“알바가 바뀌어도 서비스가 같은 매장”이 우리가 만들려는 결과다. 같은 응대란 모든 고객에게 같은 답을 한다는 뜻이 아니다. 상황이 같으면 같은 기준을 적용하고, 상황이 다르면 달라진 판단의 이유를 설명한다는 뜻이다.

## 2. 기존 서비스와 무엇이 다른가

직원용 챗봇, AI 문서 작성, 지식 재사용은 이미 존재한다. 이어받기의 차별화 가설은 **현장 사건을 회고하며 판단 이유를 기록하고, 모르는 질문에 대한 점장 결정까지 다음 직원의 근거로 남기는 흐름**이다. 독립 매장에서도 이 흐름을 운영할 수 있는지가 검증 과제다. [선정 노트 §3][선정] [I02][아이디어]

근거: [선정 노트 §3][선정]. GS25·스타벅스 사례는 당시 보도에 근거한 부분검증이다. Trainual의 AI 지식 검색·문서 작성은 노트에서 공식 기능 목록을 확인했다. 사내위키 제품은 해당 노트에서도 미조사로 남아 있다. 따라서 특정 위키 제품보다 우월하다고 주장하지 않는다.

우리가 보여 줄 장면은 다음과 같다. 신입이 쿠폰 오류를 묻는다. 근거가 부족해 점장에게 넘어간다. 점장이 확인할 조건과 처리 이유를 남긴다. 이를 승인된 사례로 저장한다. 다음에 같은 조건의 질문이 들어오면 그 사례를 근거로 답한다. 조건이 다르면 다시 확인을 요청한다. 이는 **시연 시나리오**이며 실제 매장의 해결 사례로 소개하지 않는다.

‘자동 갱신’은 AI가 매장 규칙을 마음대로 바꾼다는 뜻으로 쓰지 않는다. AI는 초안을 만들고 변경을 제안한다. 게시 권한은 사람에게 둔다. 지식 재사용과 개선 자체는 KCS에 있는 방법이다. 독창성은 이를 매장의 짧은 회고와 신입 학습에 맞게 구현하고 검증하는 데서 설명한다. [I02][아이디어] [기존 사례 정리][사례]

## 3. 평가 기준별로 보여 줄 근거·화면·숫자

평가 기준은 각 20점이다. 아래의 외부 수치는 문제와 설계의 배경이다. 자체 지표는 아직 측정 전이며, 효과의 목표값을 임의로 넣지 않는다. [공모전 규정 §9][규정]

### 문제 정의 및 필요성

문제는 쿠폰 오류·품절·교환·환불·POS 예외에서 “어떤 조건을 확인하고 누구에게 물어야 하는가”가 숙련자에게 집중된다는 것이다. 신입은 판단 근거를 찾기 어렵고, 점장은 같은 맥락을 반복해서 설명할 수 있다. 이 빈도와 부담은 현장 인터뷰로 확인해야 한다.

**근거와 숫자.** 선정 노트가 원문 확인으로 표시한 경제활동인구조사에서 2026년 8월 시간제 근로자는 **438만 2천 명**이다. 시간제 일자리의 규모를 설명하는 수치이며, 매장 알바 수나 우리 고객 수로 바꿔 쓰지 않는다. 업종별 이직률과 신입 교육시간은 확보되지 않았다. [선정 노트 §1][선정], 원출처: [정책브리핑](https://www.korea.kr/briefing/policyBriefingView.do?newsId=156785961).

**화면.** ‘질문하기’에서 처리 절차와 판단 이유를 함께 보여 준다. 근거가 없으면 점장에게 보낼 질문과 이미 확인한 조건을 보여 준다.

**우리가 측정할 숫자.** 인터뷰에서 확인한 예외 사건 수, 같은 질문의 반복 횟수, 신입의 탐색 시간, 점장의 응답 시간을 기록한다. 조사 대상과 기간을 함께 공개한다. 고객 대기시간 감소는 별도 측정 전까지 기대효과로만 적는다.

### AI 디지털 기술 활용성

AI는 말로 흩어진 경험을 사례로 정리하고, 현재 질문에 적용할 근거를 찾는 데 쓴다. 인터뷰 에이전트는 빠진 조건과 이유를 묻는다. 정리 에이전트는 사례 초안을 만든다. 검토 에이전트는 규정 충돌과 근거 누락을 표시한다. 답변 에이전트는 승인된 자료를 검색하고, 답할 수 없는 질문을 점장에게 넘긴다. 각 역할은 같은 모델을 사용할 수도 있다. 역할을 나눈다는 사실만으로 성능 향상을 주장하지 않는다.

**근거와 숫자.** Brynjolfsson·Li·Raymond의 게재본을 확인한 논문 카드에는 고객지원 직원 **5,172명**, 시간당 해결 건수 **평균 15% 증가**가 기록돼 있다. 이는 직원 보조를 검증할 이유다. 국내 매장이나 이어받기의 예상 개선율은 아니다. 기존 보고서의 14%와 혼용하지 않는다. [P07][생산성], 원출처: [QJE 게재본](https://doi.org/10.1093/qje/qjae044).

**화면.** ‘노하우 기록’에서 발화가 사례 초안으로 바뀌는 과정과 원문 근거를 보여 준다. ‘질문하기’에는 사용한 규정·사례·승인 상태를 표시한다. AI가 추정한 이유를 직원의 실제 판단처럼 저장하지 않는다.

**우리가 측정할 숫자.** 점장이 사전에 정한 채점 기준으로 답변 정답률과 근거 일치율을 측정한다. 답변 보류가 필요한 질문 중 실제로 보류한 비율도 따로 본다. 단일 처리 흐름과 역할을 나눈 흐름의 오류·지연·호출 비용을 비교해 분리의 효용을 확인한다.

### 창의성 및 차별성

핵심은 ‘왜’를 묻는 수집 방식과 해결 결과의 재사용이다. 기존 서비스 조사만으로 기능의 유일성을 증명할 수는 없다. 회고에서 얻은 조건과 이유가 일반 매뉴얼보다 실제 판단에 도움이 되는지 보여 줘야 한다. [선정 노트 §3][선정] [I02][아이디어]

**화면.** ‘점장’에서 답변을 승인하면 ‘온톨로지 그래프’에 사건·조건·조치·이유·규정의 관계가 추가된다. 관계를 누르면 출처 문장과 승인 이력을 확인할 수 있게 한다. 대기 중인 초안과 승인된 지식은 구분한다. 이어서 같은 질문에 사용할 근거가 생겼음을 보여 준다.

**우리가 측정할 숫자.** 판단 이유와 적용 금지 조건이 확인된 사례의 비율, 승인된 사례가 후속 질문에 재사용된 횟수, 재사용 후 해결률을 기록한다. 해결률은 결과가 확인된 재사용 건 중 해결된 건의 비율로 계산하고, 결과 미확인 건도 별도로 공개한다. 그래프의 노드 수를 서비스 효과로 제시하지 않는다.

### 비즈니스 서비스 타당성

구매자는 독립 카페·소규모 다점포 점주다. 사용자는 신입·숙련 직원·점장이다. 점주가 점장을 겸하더라도 구매 결정과 일상 업무는 나눠 확인한다. 반복 설명을 줄인 만큼 기록·검수 부담을 감당할 수 있다는 것이 구매 이유의 가설이다. [선정 노트 §5–6][선정]

| 구분 | 맡는 일 | 확인할 필요 |
|---|---|---|
| 구매자: 점주 | 도입·구독·근무 중 기록 시간 배정 | 기존 도구보다 순노동시간이 줄고 비용을 낼 만한가 |
| 사용자: 신입 | 조건을 확인해 질문하고 해결 여부를 남김 | 답의 적용 범위와 점장에게 물어야 할 때를 알 수 있는가 |
| 사용자: 숙련 직원 | 사건을 기록하고 판단 이유를 확인 | 기록과 되묻기가 추가 무급 노동이 되는가 |
| 사용자: 점장 | 대기 질문 응답, 검수·승인·갱신 | 새 관리 부담이 반복 설명 감소분보다 작은가 |

#### 순노동시간 계산

**절감 = 반복 설명 감소 시간 − (기록 + 되묻기 답 + 점장 검수 + 초기 구축) 시간**

단위는 매장별 참여자의 노동시간 합계다. 기록에는 초안 확인·수정을, 점장 검수에는 승인·수정·갱신을 포함한다. 초기 구축에는 자료 정리와 도입 안내를 넣는다. 같은 작업을 중복 계산하지 않는다. 초기 구축을 뺀 반복 운영 시간도 함께 제시하되 전체 절감을 대신하지 않는다.

반복 설명 감소 시간은 비교 조건의 설명 시간에서 도입 조건의 설명 시간을 뺀 값이다. 점장의 새 답변·후속 설명도 도입 조건에 포함한다. 문의 유형·건수와 근무시간을 함께 적어 업무량 차이를 드러낸다. 고객 대기시간과 신입 탐색 시간은 별도 지표다. 대기 중 다른 일을 한 시간까지 노동시간으로 더하지 않는다.

‘지표’에는 분자·분모와 시드 제외 보기가 있다. 기록·되묻기·검수·초기 구축 시간의 자동 측정은 이번 변경에 포함되지 않는다. 파일럿에서는 별도 관찰표에 작업 시작·종료와 종류를 적는다. 실행 로그의 처리 시간을 사람의 노동시간으로 대신하지 않는다.

#### 2주 파일럿 설계 — 미실행

대상은 독립 카페·소규모 다점포 중 매장 1~2곳이다. 점주와 직원의 동의를 받고 근무시간 안에서 진행한다. 아래는 계획이며 효과 수치가 아니다. 모의 매장 결과를 실제 매장 결과에 합치지 않는다.

| 항목 | 설계 |
|---|---|
| 기간·비교군 | 2주 동안 기존 종이 매뉴얼/단톡방 조건과 이어받기 조건을 비교한다. 같은 매장의 비교 가능한 교대·문의 유형을 배정한다. 조건별 관찰 기간과 배정 방식은 시작 전에 기록한다 |
| 비교 조건 | 쿠폰·품절·환불 등 같은 유형의 문의를 비교한다. 두 조건 모두 같은 규정을 쓰고 점장에게 질문할 수 있다. 업무량·숙련도·교대 차이를 남긴다 |
| 노동 지표 | 반복 설명 횟수·시간, 기록·되묻기 답·점장 검수·초기 구축 시간을 관찰한다. 위 식으로 매장별 순절감을 계산한다 |
| 응답 지표 | 탐색 시간, 미해결 대기 시간, 재사용 건수, 해결 건수/결과 확인 건수, 결과 미확인 건수, 필요한 점장 이관 건수/이관이 필요한 문의 건수를 집계한다. 점장이 규정과 결과를 대조한다 |
| 운영·구매 지표 | 근무 외 기록 여부, 임시 저장·재개, 크레딧 선택 존중 여부, 기록 압박 경험을 확인한다. AI 호출·저장 비용과 지불 의향은 별도로 적는다 |
| 측정 시점 | 초기 구축부터 종료까지 노동시간을 기록한다. 근무 중 작업별 관찰과 근무 종료 전 확인을 병행한다. 인터뷰는 도입 전과 종료 때 진행한다 |
| 중단 조건 | 무급 기록 요구, 기록 거부에 대한 불이익, 개인정보 노출, 잘못된 답의 현장 적용이 확인되면 해당 사용을 즉시 중단한다. 점장 검수가 불가능한 범위는 보류한다. 추가 노동이 절감보다 크면 수집 범위를 줄이고, 부담이 계속되면 파일럿을 중단한다 |
| 결과 해석 | 매장·역할별 관찰 건수와 기간, 실패·미응답을 공개한다. 시드는 제외한다. 적은 매장과 짧은 기간의 결과를 매출·이직 감소나 전체 업종 효과로 일반화하지 않는다 |

같은 매장에서는 먼저 배운 답이 다른 조건에 영향을 줄 수 있다. [추론] 조건 순서와 이미 접한 사례를 남겨 이 한계를 함께 해석해야 한다. 구매 의향은 실제 결제와 구분한다.

### 기술 현실적 실현 가능성

최소 구현은 사례 저장, 승인 상태 관리, 근거 검색, 답변 보류, 점장 답변의 재저장을 잇는 흐름이다. POS 직접 제어 없이도 지식 순환을 시연할 수 있다. 온톨로지는 사건·조건·조치·이유·규정 등 항목의 종류와 관계를 정의해 구성한다. 저장된 관계가 바뀔 때 그래프를 갱신한다. 검색에 그래프를 실제로 사용하지 않는 단계에서는 시각화 기능으로 설명한다.

**근거와 화면.** 정천수의 Graph Agent 논문 카드는 검색 정보의 신뢰성을 평가·종합하는 구현을 소개한다. 이는 처리 흐름의 참고 근거다. LangGraph의 실행 흐름과 화면의 지식그래프는 다른 개념이다. ‘질문하기 → 점장 → 그래프 → 재질문’에서 저장과 재검색이 실제로 이어지는지 확인한다. [P19][그래프]

**범위와 숫자.** 초기 I02의 최소 구현안은 학교 앞 카페 **1곳 또는 모의 매장**, 사례 **30개**다. 이는 초기 계획이며 확보한 데이터 수가 아니다. 이번 현장 검증은 위의 2주 파일럿으로 구체화했다. 종이 매뉴얼/단톡방과 이어받기를 비교한다. 정답률, 탐색 시간, 적절한 승인 요청 여부, 응답 지연, 건당 비용을 측정한다. 사례를 만든 자료와 평가 질문을 구분하고, 참여자 수·실패 건수·측정 조건을 공개한다. [I02][아이디어]

필수 검증에는 근거 없음, 규정 충돌, 만료된 사례, 다른 매장 자료 접근, 점장 부재를 포함한다. 점장이 답하기 전에는 미해결 상태와 기존 근거가 허용하는 확인 절차만 보여 준다. 훈련 뒤에는 AI 없이 푸는 지연 과제로 학습이 남았는지 본다. 핵심 성과가 기존 방식보다 나아지지 않거나 운영 부담이 편익을 넘으면 범위를 줄인다. [I02][아이디어]

### 그림자노동 비판에 대한 운영 원칙

고객에게 새 작업을 요구하지 않아도 직원의 기록 부담은 늘 수 있다. 근무시간 내 기록만으로 순노동 절감이 입증되지는 않는다. 아래 원칙은 파일럿 운영 조건이다. 임시 저장과 크레딧 표시 선택은 이번 변경에 포함됐다. 나머지 원칙의 준수는 현장에서 확인해야 한다. [학회 맥락 노트 Q1][맥락] [선정 노트 §5][선정]

| 원칙 | 운영 방법 | 확인할 지표·증거 |
|---|---|---|
| 근무시간 내 | 기록·되묻기·검수를 근무에 포함한다. 퇴근 뒤 작성을 요구하지 않는다 | 근무 외 작업 건수·시간, 무급 작성 요구 여부. 직원 확인과 근무표를 대조한다 |
| 짧은 기록 | 반복되거나 어려웠던 사건만 남긴다. 기록량 목표를 두지 않는다 | 기록·수정·되묻기 시간, 중단 건수, 기록량 압박 경험 |
| 나중에 확인 | 임시 저장 후 한가할 때 근무시간 안에서 확인한다. 미완성을 불이익으로 삼지 않는다 | 임시 저장·재개 건수, 미완성 사유, 재촉·불이익 경험 |
| 크레딧 표시 선택 | 직원이 공개 표시 여부를 고른다. 기여량을 인사평가나 순위 경쟁에 쓰지 않는다 | 표시 선택과 실제 공개의 일치 여부, 표시 강요·평가 활용 경험 |
| 질문자 개인 통계 없음 | 질문자별 횟수·오답·순위를 만들지 않는다. 결과는 매장·역할 단위로 집계한다 | 수집 항목·보고서 점검, 개인 통계 생성·요구 여부. 크레딧 선택과 별도로 확인한다 |

이 지표는 아직 측정하지 않았다. 점주 응답만으로 준수를 판정하지 않고 직원에게도 확인한다. 노동시간 관찰 자료는 질문자 평가 자료로 전환하지 않는다. 원칙 위반 때는 파일럿 중단 조건을 적용한다.

## 5. 심사위원이 물을 질문과 정직한 답

### “GS25나 스타벅스에도 직원용 AI가 있는데, 무엇이 새롭습니까?”

직원용 AI 자체는 새롭지 않습니다. 우리는 매장의 실제 사건에서 이유와 적용 조건을 묻고, 점장이 해결한 질문을 다시 쓸 수 있는 사례로 남기는 과정에 집중합니다. 기존 서비스에 이 기능이 전혀 없다고 확인한 것은 아닙니다. 독립 매장에서 이 과정을 적은 부담으로 운영할 수 있는지가 차별화의 검증 과제입니다.

### “숙련자와 점장이 바쁜데, 누가 계속 기록합니까?”

AI가 회고를 정리해도 확인과 승인은 사람의 일로 남습니다. 근무시간 안에서 기록하고, 모든 사건을 의무적으로 입력하게 하지 않겠습니다. 반복되거나 판단이 어려웠던 사건부터 다룹니다. 기록·검수 시간과 줄어든 반복 설명 시간을 함께 재겠습니다. 추가 부담이 더 크면 기록 범위를 줄여야 합니다.

### “AI가 틀리거나 점장의 잘못된 관행이 쌓이면 어떻게 합니까?”

승인됐다고 반드시 옳은 것은 아닙니다. 현재 데모는 만료·상충 카드를 답변 근거에서 제외합니다. 허위 인용·금지 표현 줄을 지운 뒤 남는 답이 없거나 점장 호출 기준에 해당하면 점장에게 넘깁니다. 점장 답에 금지 표현이 있으면 승인 대기로 저장하고 승인 때 다시 검사합니다. 질문·기록·점장 답의 개인정보는 실행 기록·저장 전에 가립니다. 다만 문장 내용의 사실 여부와 공식규정 원문·버전은 확인하지 못합니다. 계정·권한과 매장별 데이터 분리도 실제 배포 전에 필요합니다.

### “여러 에이전트와 온톨로지 그래프가 꼭 필요합니까?”

역할을 나누면 어디서 누락과 충돌을 확인했는지 추적하기 쉽습니다. 다만 비용과 시간이 늘 수 있어 단일 처리 흐름과 비교해야 합니다. 그래프는 어떤 조건과 이유가 답변에 연결됐는지 확인하는 도구로 씁니다. 보기 좋은 연결선만으로 정확도가 높아졌다고 말하지 않겠습니다. 검색에 관계 정보를 쓰는 경우에는 그 기능을 뺀 조건과 비교하겠습니다.

### “효과가 있다는 증거와 돈을 낼 고객이 있습니까?”

현재 자료에는 다른 조직의 AI 보조·지식공유 연구가 있습니다. 이어받기의 현장 성과나 유료 고객을 입증한 자료는 없습니다. 실제 매장 1~2곳에서 2주 동안 종이 매뉴얼/단톡방과 비교할 계획입니다. 정답률과 탐색 시간뿐 아니라 AI 없이 남는 학습, 점장의 관리 부담도 보겠습니다. 구매 의향은 별도로 확인하고, 시간 절감만으로 매출이나 이직 감소를 단정하지 않겠습니다.

## 8. 2차 심사 지적과 반영

근거는 [Opus 2차 심사](../judge/r2_opus.md)와 [Astra 2차 심사](../judge/r2_astra.md)다. 아래는 전달받은 코드 변경을 반영한 내용이다. 이번 문서 작업에서는 코드 수정이나 테스트 재실행을 하지 않았다. LLM 모드의 품질·비용은 여전히 미실측이다.

| 지적 | 바꾼 것 | 남은 한계 |
|---|---|---|
| Astra: ‘공식규정’이라는 말만 있으면 무인용 문장이 남음 | 검증 예외를 없앴다. 근거 없는 줄은 해당 표현이 있어도 삭제한다 | 유효 인용이 붙은 문장의 의미와 사실 여부는 보장하지 못한다. 이유·임시 행동까지 같은 수준으로 검증됐다고 볼 수 없다 |
| 두 심사: 금액 기준을 글자 일치로 판정함 | 숫자로 비교한다. 3만원 이상 기준에 2만원 질문은 해당하지 않고, 5만원은 점장에게 넘긴다 | 모든 부정·복합 조건의 해석을 검증한 것은 아니다 |
| Opus: 위험 상황을 바꿔 말하면 호출 기준을 놓침 | `harness/policies/forbidden-phrases.json`의 `alwaysEscalate`에 안전 어휘 안전망을 뒀다. 건강 이상·부상·폭력·시설 위급·범죄 의심 어휘가 있으면 위키가 답하지 않고 점장에게 넘기며 119/112를 안내한다. 두드러기·미끄러짐·때리려고도 잡는다 | 목록에 없는 표현은 여전히 놓칠 수 있다 |
| Astra: 승인 대기 점장 답이 신입에게 보이고 질문도 닫힘 | 금지 표현으로 승인 대기가 된 답은 신입에게 보이지 않는다. 카드가 승인될 때 질문을 닫는다 | 점장 신원·권한과 답 내용의 사실 여부는 확인하지 못한다 |
| Opus: ‘안 된다’는 사실 서술을 금지로 분류함 | 규칙 모드의 금지 판정을 ‘하지 않/하지 말/금지/절대/면 안 된’으로 좁혔다 | 문장 패턴에 따른 분류다. 판단 이유의 정확성과 LLM 모드의 품질은 미실측이다 |
| 두 심사: 질문자 개인 통계와 비공개 크레딧 노출 | 그래프의 질문자는 신입들 같은 역할 묶음으로만 표시한다. 개요·위키 사람 페이지의 개인별 질문 수를 없앴다. 크레딧을 끈 카드는 ‘이름 비공개’로 연결한다 | ‘내가 물은 질문’을 위해 `askerId`는 저장한다. 계정·권한이 없어 접근 통제는 하지 않는다 |
| Opus: 반복 점검 기록과 영문 에이전트 ID가 화면을 어지럽힘 | 화면 진입 점검은 실행 기록을 남기지 않는다. 오케스트레이터 요약은 한국어 에이전트 이름을 쓴다 | 그래프 라벨 겹침과 실제 사용자의 탐색 부담은 별도 확인이 필요하다 |
| Opus: 답의 이유가 숨고 카드 번호가 반복됨 | 이유 한 줄을 답 아래에 펼쳤다. 카드 번호는 답 끝에 한 번 표시한다. 안전 상황은 경고 상자로 보여 준다 | 답의 이해도나 대응 오류 감소는 측정하지 않았다 |
| 두 심사: 규칙 모드를 AI 회고처럼 안내함 | 노하우 남기기의 규칙 모드는 ‘기본 질문’으로 표시한다 | 회고 품질과 수정 시간, LLM 대비 차이는 미실측이다 |
| 두 심사: 점검 목록이 길고 공식규정을 쉽게 보관함 | 점검 결과를 기본으로 접었다. 공식규정 카드 보관 때 확인과 사유 입력을 받는다 | 공식규정 원문·버전·확인자 검증은 없다. 검수 시간도 미측정이다 |
| Opus: 훈련 입력 안내가 없고 문서가 변형 출제를 주장함 | ‘무엇을 할지·왜·하면 안 되는 것’을 안내한다. 실제 사례의 상황 그대로 출제한다고 화면과 문서에 적었다 | 조건 변형 출제와 학습 효과는 확인되지 않았다 |
| 두 심사: 기존 테스트가 새 결함을 놓침 | 테스트를 23개에서 28개로 늘렸다. 무인용 예외·금액 비교·안전 표현·승인 후 질문 종료·금지 분류를 추가했다 | 모든 표현과 출력 경로를 검증한 것은 아니다. 이번 문서 작업에서는 재실행하지 않았다 |
| 두 심사: AI 품질·순노동 절감·지불 의향 근거 부족 | 수정한 통제와 미측정 효과를 구분해 적었다 | LLM 품질·비용, 현장 효과, 기록·검수 시간과 지불 의향은 여전히 미실측이다 |
