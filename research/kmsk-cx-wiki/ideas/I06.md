# I06 · 조건을 지키는 여행 추천

좋아 보이는 추천보다 실제 이용 가능한 선택지

[위키 홈](../README.md) · [후보 비교](ideas.md) · [검증 계획](../validation.md)

## 고객과 해결할 문제

유모차·이동 제약·시간 제약 때문에 추천받은 장소를 실제 이용하지 못하는 여행자.

## 만들고 싶은 고객 경험

필수 조건과 정보의 확인 시점을 보고 선택하며 틀린 정보를 수정한다.

## 고객 여정

필수 조건 입력 → 검증된 시설 정보 필터 → 후보와 제외 이유 → 이용 후 오류 제보 → 검토 후 지식 수정.

## 지식경영 기여

사실 조건과 취향을 구분하고 이용 불가 사유·정보 신선도를 관리.

## 기존 서비스와의 차이 — 검증 전 가설

일반 여행 챗봇과 차별성이 약하다. 한 지역·한 고객 집단의 검증된 접근 조건에 집중.

## 학생 팀의 최소 구현

학교 주변 시설 20곳을 직접 확인해 데이터 구축. 실시간 예약 없이 조건 충족 후보만 제안.

## 검증 실험과 지표

일반 추천과 조건 기반 추천을 비교해 필수 제약 위반률과 검증 시간을 측정.

측정 지표: 제약 위반률, 정보 갱신 비용, 실제 방문 가능률, 선택 만족.

## 고객과 사업성 가설

관광지 운영자나 여행업체 대상 가설이나 지불 의사는 미확인.

## 취약점·중단 조건

실시간 접근성 정보 확보가 어려우며 잘못된 접근 안내의 영향이 크다. 확인 날짜와 미확인 표시 필수. 기존 방식보다 핵심 성과가 좋아지지 않거나 추가 운영 부담이 편익을 넘으면 범위를 줄이거나 다른 후보를 선택한다.
