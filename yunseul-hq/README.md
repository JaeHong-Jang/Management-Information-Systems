# 윤슬 HQ

역전할머니맥주 본사가 리뷰로 매장별 응대 편차를 찾고, 안내가 어긋난 상황을 다음 근무자가 쓸 사례 카드와 브리핑으로 바꾸는 서비스다.

## 같은 브랜드에서 손님이 겪는 차이

| 문제를 보여 주는 수치 | 의미 |
|---|---|
| 1.3~4.9점 | 카카오 별점이 10개 이상인 역전할머니맥주 매장의 최저·최고 평점이다. |
| 36% | 같은 표본에서 평점이 3.0점 미만인 매장의 비율이다. |
| 28건 | 강남 윤슬점의 원형이 된 매장의 1~2점 리뷰 82건 중 정책·규칙으로 자동 분류된 건수다. 다른 불만과 중복될 수 있다. |

(출처: docs/research_가맹점_편차.md. 브랜드 분포 집계는 data/source/브랜드_편차_요약.csv에도 수록돼 있다.)

## 사용자와 화면

본사 SV·점장·직원은 하나의 반응형 웹을 쓴다. 상단바에서 역할을 바꾸면 담당 업무에 맞는 메뉴가 열린다. 넓은 화면에서는 왼쪽 메뉴로, 좁은 화면에서는 하단 탭으로 이동한다.

| 역할 | 화면과 쓰임 |
|---|---|
| 본사 SV | 전국 현황 `/hq`의 지도와 순위에서 매장을 골라 상세 `/hq/stores/:id`에서 원인·처방·가상 결과를 확인한다. 리뷰 탐색 `/hq/reviews`에서 원문을 읽고, 지식 그래프 `/graph`에서 원인과 카드의 연결을 본다. 표준 개정 제안은 본사 전용 화면 `/hq/standards`에 모인다. 에이전트 운영 `/hq/agents`에서는 팀 구성과 실행 기록을 본다. |
| 점장 | 오늘 할 일 `/store/:id/manager`에서 받은 처방을 확인하고 카드를 승인하며 직원 질문에 답한다. 매장 위키 `/store/:id/wiki`와 지식 그래프 `/graph`에서 근거 카드를 찾는다. |
| 직원 | `/store/:id/staff`에서 오늘 브리핑을 읽고, ‘물어보기’에서 근거 카드로 답을 찾거나 점장을 호출한다. ‘기록하기’에서 근무 경험을 남기고 매장 위키 `/store/:id/wiki`에서 승인 카드를 읽는다. |

## 에이전트 팀

| 팀 | 구성 | 담당 |
|---|---|---|
| lead | 오케스트레이터 | 흐름을 시작하고 실행 기록을 잇는다. |
| monitor | 리뷰 수집원, 불만 분류원, 편차 채점원 | 익명 리뷰를 분류하고 공개 산식으로 순위를 계산한다. |
| diagnose | 원인 분석가, 표준 차이 탐지원 | 불만의 원인과 가상 표준에서 벗어난 사례를 찾는다. |
| prescribe | 처방 카드 작성자, SV 과제 설계자, 브리핑 작성자 | 원인에 따라 카드·방문 과제·근무 안내를 작성한다. |
| capture | 개인정보·익명화 가드, 회고 인터뷰어, 사례 카드 편집자 | 직원 경험과 판단 이유를 승인 대기 카드로 정리한다. |
| answer | 검색 사서, 현장 코치, 점장 연결 | 근거 카드로 답하고 해결하기 어려운 질문을 점장에게 보낸다. |
| verify | 리뷰 인용 검증, 카드 인용 검증, 표준 우선 검증, 표현 검증 | 원문과 카드 인용, 규정 충돌, 안내 표현을 확인한다. |
| keeper | 종합 편집자, 위키 점검관, 표준 승격 제안자 | 토픽을 정리하고 카드 충돌과 표준 개정 필요성을 찾는다. |

(화면·팀 구성 출처: docs/PLAN.md §2·6)

## 실행 방법

두 터미널을 열어 하나는 `backend/`, 다른 하나는 `frontend/`에서 각각 `npm install && npm run dev`를 실행한다. 백엔드는 8788 포트를 쓰고, 프론트엔드는 브라우저에서 `http://localhost:5176`으로 연다.

## 데이터와 시연 범위

카카오맵 매장별 별점·리뷰와 네이버 플레이스의 매칭 매장 첫 페이지 리뷰·키워드 투표를 사용한다. 브랜드는 실명이고 강남 윤슬점을 비롯한 매장은 익명이다. 실제 매장명·주소·장소 식별자·작성자 정보는 시연에 표시하지 않는다. 본사 표준은 공모전용 가상 표준이다. 처방 전에는 실제 익명 리뷰를 쓰며, 처방 후 4주 리뷰와 효과 수치는 모두 가상이다. (출처: data/source/README.md, docs/PLAN.md §1·8)

서비스의 설계 배경과 파일럿 가설은 [기획구상안](docs/기획구상안.md), 배점과 처방 기준은 [진단 체계](docs/진단_체계.md)에 정리했다.

발표 순서와 화면별 조작은 [시연 대본](docs/시연_대본.md)에 정리했다.
