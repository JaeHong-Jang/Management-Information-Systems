# 윤슬 HQ

역전할머니맥주 직원이 근무 중 막히면 매장 카드에서 답을 찾고, 카드에 없는 대처법은 선배·점장의 답으로 남겨 새 알바가 첫 근무 전에 읽어요.

## 사용자와 화면

처음 `/`를 열면 강남 윤슬점 **직원 홈**이 나와요. 상단에서 직원, 점장, 본사 SV 순으로 역할을 바꿔요.

| 역할 | 화면과 쓰임 |
|---|---|
| 직원 | 홈 `/store/:id/staff`에서 ‘지금 막혔어요’로 묻고 오늘 브리핑을 읽어요. ‘첫 근무 준비’에서 상황 카드를 읽고 ‘읽었어요’를 눌러요. ‘기록하기’에서 경험을 남기고 매장 위키 `/store/:id/wiki`에서 승인 카드를 찾아요. |
| 점장 | `/store/:id/manager`에서 넘어온 질문에 답해 카드로 남겨요. 새 알바가 아직 읽지 않은 상황과 매장 카드가 없는 상황을 확인해요. 카드 작성·승인과 위키 점검도 여기서 해요. |
| 본사 SV | 전국 상황 `/hq`에서 여러 매장에 반복되는 불만과 공유할 브랜드 카드를 봐요. 매장 비교, 카드·표준, 에이전트 화면을 이용해요. 리뷰 탐색과 지식 그래프에서 근거를 확인해요. |

## 리뷰를 보는 이유

카카오 별점이 10개 이상인 매장의 평점은 1.3~4.9점이고, 36%가 3.0점 미만이에요. 강남 윤슬점의 1~2점 리뷰 82건 중 정책·규칙 불만은 28건이에요. 한 리뷰에 여러 불만이 잡힐 수 있어요. 어떤 상황에서 손님이 불편을 겪었는지 원문을 읽고 카드 우선순위에 반영해요. [조사 근거](docs/research_가맹점_편차.md)

## 에이전트 팀

| 팀 | 구성 | 담당 |
|---|---|---|
| lead | 오케스트레이터 | 흐름을 시작하고 실행 기록을 이어요. |
| monitor | 리뷰 수집원, 불만 분류원, 편차 채점원 | 익명 리뷰를 분류하고 공개 산식으로 순위를 계산해요. |
| diagnose | 원인 분석가, 표준 차이 탐지원 | 불만의 원인과 가상 표준에서 벗어난 사례를 찾아요. |
| prescribe | 처방 카드 작성자, SV 과제 설계자, 브리핑 작성자 | 원인에 따라 카드·방문 과제·근무 안내를 작성해요. |
| capture | 개인정보·익명화 가드, 회고 인터뷰어, 사례 카드 편집자 | 직원 경험과 판단 이유를 승인 대기 카드로 정리해요. |
| answer | 검색 사서, 현장 코치, 점장 연결 | 근거 카드로 답하고 해결하기 어려운 질문을 점장에게 보내요. |
| verify | 리뷰 인용 검증, 카드 인용 검증, 표준 우선 검증, 표현 검증 | 원문과 카드 인용, 규정 충돌, 안내 표현을 확인해요. |
| keeper | 종합 편집자, 위키 점검관, 표준 승격 제안자 | 토픽을 정리하고 카드 충돌과 표준 개정 필요성을 찾아요. |

화면 구성은 [개편 원본](docs/PIVOT.md), 팀별 역할은 [구현 계획 §6](docs/PLAN.md)에서 확인해요.

## 실행 방법

두 터미널을 열어 하나는 `backend/`, 다른 하나는 `frontend/`에서 각각 `npm install && npm run dev`를 실행해요. 백엔드는 8788 포트를 쓰고, 프론트엔드는 브라우저에서 `http://localhost:5176`으로 열어요.

## 데이터와 시연 범위

카카오맵 매장별 별점·리뷰와 네이버 플레이스의 매칭 매장 첫 페이지 리뷰·키워드 투표를 사용해요. 브랜드는 실명으로 쓰고 강남 윤슬점을 비롯한 매장은 익명이에요. 실제 매장명·주소·장소 식별자·작성자 정보는 시연 화면에서 가려요. 본사 표준은 공모전용 가상 표준이에요. 처방 전에는 실제 익명 리뷰를 쓰며, 처방 후 4주 리뷰와 효과 수치는 모두 가상이에요. 본사 표준과 처방 후 결과에는 ‘가상’ 표지를 붙여요. (출처: data/source/README.md, docs/PLAN.md §1·8)

서비스의 설계 배경과 파일럿 가설은 [기획구상안](docs/기획구상안.md), 배점과 처방 기준은 [진단 체계](docs/진단_체계.md)에 정리했어요.

발표 순서와 화면별 조작은 [시연 대본](docs/시연_대본.md)에 정리했어요.
