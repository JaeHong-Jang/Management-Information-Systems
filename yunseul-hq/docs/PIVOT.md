# 윤슬 HQ v3 개편 브리프: 직원이 막히는 순간 중심

v2는 본사 SV의 전국 위험 순위가 첫 화면이었다. 사용자가 원한 문제는 그게 아니다. 이 문서가 v3 작업의 원본이고, `docs/PLAN.md`·`docs/DESIGN.md`·`docs/REDESIGN.md`와 다르면 이 문서가 이긴다. 타입은 `shared/contracts.ts`의 `SituationDef`·`Situation`·`Onboarding`·`BrandSituation`과 `StoreState.situations`·`StoreState.onboarding`·`HqOverview.situations`가 원본이다.

## 1. 문제 (사용자 원문 요지)

> 직원들이 겪는 어려운 문제들이 있다. 새 알바가 들어오면 그걸 다시 배워야 하고, 갑작스러운 상황에 대처하지 못한다. 이게 매장마다 서비스가 달라지는 이유다.

그래서 v3의 주인공은 **새 알바와 그를 가르치는 선배·점장**이다. 본사는 보조다.

## 2. 사용자 결정 (확정)

1. 첫 화면은 **직원 화면**. 역할 전환 순서는 직원 / 점장 / 본사 SV. 기본 역할은 직원.
2. 새 알바 첫 근무 준비는 **상황 카드 읽기만**. 퀴즈·점수·연습 문제 없음(예전 프로젝트에서 '훈련' 기능을 지운 적이 있다). '읽었어요' 표시와 진행률만.
3. 본사 대시보드는 **축소해서 근거로 유지**. 지우지 않는다. 메뉴와 첫 화면에서 뒤로 뺀다.

## 3. 화면

공통 셸(AppShell·TopBar·사이드바/하단 탭), 브랜드 색·폰트, 색 규칙(빨강은 '고위험'에만), 해요체·이모지 금지는 v2 그대로다.

### 3.1 직원 (`/store/:id/staff`) — 첫 화면

메뉴(사이드바·하단 탭): **홈 / 첫 근무 준비 / 기록하기 / 매장 위키**. `?tab=home|prep|record`. 예전 `?tab=brief`·`?tab=ask`는 홈으로 연다.

홈(`tab=home`, 기본):
1. 맨 위 **"지금 막혔어요"** 묻기 상자. 큰 입력창 + 52px 버튼. 그 아래 이 매장에서 자주 터지는 상황 칩(`situations` 상위 5개 title). 칩을 누르면 그 상황 문장이 입력창에 들어간다(바로 보내지 않음). 답은 같은 자리 아래에 v2 AskTab처럼 나온다(답 + 왜 + 근거 카드 칩 + 해결/점장에게 넘기기).
2. 신입(`role === '신입'`)이고 첫 근무 준비를 다 읽지 않았으면 노랑 띠: "첫 근무 준비 3/8장 읽었어요 · 이어서 보기".
3. **오늘 브리핑**(v2 BriefingTab 내용, 말풍선 '손님께 할 말').

첫 근무 준비(`tab=prep`):
- 상단: "이 매장에서 실제로 자주 터진 상황부터 읽어요" + 진행 막대(읽은 수/전체).
- `onboarding.items` 순서대로 카드 하나씩 세로 목록(펼친 상태). 각 카드:
  - 상황 제목(`situationTitle`) — 큰 글씨
  - 왜 이게 먼저인지(`why`, 예: "이 매장 리뷰 12건에서 이 상황이 불만이 됐어요")와 리뷰 인용 1줄(`situations[].quotes[0]`, 형광펜 없이 회색 인용)
  - 카드 본문: 이렇게 해요(actions), 왜(reason), 하지 말 것(avoid), 손님께 할 말(customerNotice, 말풍선), 이럴 땐 점장 부르기(escalateWhen), 출처 배지(본사 표준/현장노하우)
  - '읽었어요' 버튼 → 읽음 표시(시각). 이미 읽은 카드는 접힌 한 줄 + 체크.
- 다 읽으면 "첫 근무 준비를 마쳤어요. 막히면 홈에서 바로 물어보세요" 빈 상태(말풍선).

'나' 선택(사람 고르기)은 v2처럼 화면 상단에 둔다. 기본값은 신입 중 첫 사람(P006 최도윤, 3일차)이다.

기록하기·매장 위키: v2 그대로.

### 3.2 점장 (`/store/:id/manager`)

순서를 이렇게 바꾼다.
1. 오늘 할 일 한 줄: 넘어온 질문 n · 카드 없는 상황 n · 첫 근무 준비 중인 신입 n명 · 승인 대기 n.
2. **넘어온 질문**(v2 QuestionsPanel). 점장이 답하면 카드가 된다는 문구.
3. **새 알바 준비 상태**: 신입마다 이름·근무 기간·읽은 카드 k/N 막대·안 읽은 상황 제목 목록.
4. **우리 매장 상황 표**: 상황 / 리뷰 불만 수(이 매장 비율 vs 브랜드 비율) / 카드(매장 카드 수·브랜드 카드 수, 카드 번호 칩) / 직원 질문 수(미답 수) / 상태. `gap`이면 노랑 '카드 없음' 배지와 '카드 만들기' 버튼 → 기존 카드 생성 API로 상황 제목·주제가 채워진 작은 폼(제목·상황·왜·이렇게 해요·하지 말 것·점장 부를 때·손님께 할 말)을 열고, 저장하면 점장 작성이라 바로 승인 카드가 된다(기존 API 동작을 따른다. 승인 대기로 가면 그대로 둔다).
5. 승인 대기 카드(v2).
6. 위키 점검(v2 LintPanel).
7. 본사에서 받은 처방·매장 진단 요약은 맨 아래 접힌 영역(`<details>`)으로.

### 3.3 본사 SV (`/hq`)

메뉴를 줄인다: **전국 상황 / 매장 비교 / 카드·표준 / 에이전트**. 리뷰 탐색과 지식 그래프는 '근거' 그룹 한 칸씩 남기되 뒤로.
- `/hq` 전국 상황(첫 본사 화면): 맨 위 "전국에서 자주 터지는 상황" 표(`overview.situations`: 상황 / 브랜드 비율 / 상위 3위 안에 드는 매장 수 / 브랜드 카드 칩). 그 아래 KPI 줄과 위험 순위 표(v2). 지도·분포·히트맵·지역 요약은 `<details>` "전국 지도와 분포 더 보기" 안으로 접는다.
- 매장 상세·리뷰·표준·에이전트 화면은 v2 그대로 둔다.

### 3.4 라우팅

- `/` → 역할에 따라: 직원 `/store/{타깃}/staff`, 점장 `/store/{타깃}/manager`, SV `/hq`. 타깃 id는 overview에서 오기 전까지 로딩 표시.
- localStorage 역할 키를 새 키(`yunseul-hq.role.v3`)로 바꿔 기존 사용자도 직원으로 시작하게 한다.

## 4. 규칙 (백엔드 `backend/src/rules/situations.ts`, 순수 함수)

상황 정의(상수, 이 순서로 id 부여):

| id | title | complaintTypes | cardTopics |
|---|---|---|---|
| T01 | 이용시간이 다 됐다고 알려야 할 때 | 이용시간제한, 규칙 미고지·말바꿈 | 이용시간 |
| T02 | 인원·자리 때문에 손님이 불편해할 때 | 좌석·인원 | 좌석 배정, 단체 예약 |
| T03 | 최소주문을 물어보거나 요구받을 때 | 최소주문 | 최소주문 |
| T04 | 주문한 메뉴나 술이 떨어졌을 때 | 품절·대체 | 품절·대체, 주류·케그 |
| T05 | 계산·중간결제가 꼬였을 때 | 결제·계산 | 결제·계산 |
| T06 | 신분증 확인이 애매할 때 | 신분증 | 신분증 |
| T07 | 음식에서 이물이 나오거나 위생 지적을 받을 때 | 위생 | 이물·위생 |
| T08 | 손님이 오래 기다린다고 할 때 | 대기·서빙지연 | 응대 기본 |
| T09 | 불친절하다는 말을 들을 때 | 직원 태도 | 응대 기본 |
| T10 | 많이 취한 손님이나 계산 분쟁이 생겼을 때 | (없음) | 취객·분쟁 응대 |

- `storeReviews`: 그 매장 실제 리뷰(virtual 제외) 중 complaintTypes 중 하나라도 태그된 수. `storeShare` = storeReviews / (불만 태그가 하나라도 붙은 그 매장 리뷰 수), 분모 0이면 0. `brandShare`는 전 매장 실제 리뷰로 같은 방식.
- `quotes`: 해당 태그 리뷰 중 별점 낮은 순 → 최신 순으로 2개, 본문 120자에서 자름.
- `cardIds`: `storeCards(storeId)` 중 status approved이고 topic이 cardTopics에 있는 카드. 매장 카드 먼저, 그다음 브랜드 카드, 각 안에서 id 순.
- `questions`/`openQuestions`: 그 매장 질문 중 `cited`에 이 상황 카드가 있거나, 질문 본문에 이 상황 카드들의 tags 중 하나가 들어 있는 것. open = status가 escalated(답 대기)인 것(실제 상태값은 contracts의 QuestionStatus를 따른다).
- `gap` = storeReviews ≥ 3 이고 storeCard가 false.
- `priority` = storeReviews × 2 + questions × 3 + (gap ? 5 : 0) + (T10이면 4: 리뷰엔 안 남지만 매장 사고로 이어지는 상황). 동점이면 id 순.
- 온보딩 `items`: priority 순으로 cardIds가 있는 상황마다 첫 카드 1장(매장 카드 우선), 최대 8장. `why`: storeReviews > 0이면 "이 매장 리뷰 {n}건에서 이 상황이 불만이 됐어요", 아니고 questions > 0이면 "직원들이 {n}번 물어본 상황이에요", 아니면 "본사 기본 응대예요".
- 읽음 기록은 db에 `onboardingReads: OnboardingRead[]`로 저장(시드 비어 있음, P005 이지우는 시드에서 3장 읽은 상태로 넣어 진행 중 모습을 보이게 한다). 같은 사람·카드 중복 저장 안 함.
- `BrandSituation.storesTop3`: 순위 대상 매장마다 상황별 storeReviews 상위 3개(0 제외)에 들면 1.

## 8. v3.1 사용성 개선 (P0·P1, 사용자 승인)

근거: 과거 공모전 폴더 조사와 v3 사용성 점검. 핵심은 '막힘 → 점장 답 → 카드' 순환이 직원 쪽에서 끊겨 있었다는 것이다. 타입 변경: `Question.situationId?`, `Question.nearCardId?`, `StoreState.now`.

### 8.1 백엔드

1. **상황 버튼 직행**: `POST /api/stores/:id/ask` body에 `situationId?`. 있으면 검색(librarian) 대신 그 상황의 `cardIds[0]`(매장 카드 우선) 카드로 답한다. confidence high, cited [그 카드], status answered. 질문 기록과 실행 기록은 평소처럼 남긴다. 없는 situationId면 400.
2. **넘길 때도 지금 할 일**: 넘김(escalated)이 되면 가장 가까운 카드(검색 1위, 점수가 낮아도)를 `nearCardId`로 저장한다. 안전 상황이면 nearCardId 없음. 답 문구에서 사실이 아닌 '바로 알렸어요'를 뺀다. 넘김 기본 문구: "매장 위키에 딱 맞는 사례가 아직 없어요. 지금은 점장님을 직접 불러 주세요. 질문은 점장님 할 일에 올라가 있고, 답이 오면 여기 '내 질문'에 보여요." 점장 호출 기준 문구도 "점장님을 직접 불러 주세요. 그동안 할 수 있는 것:"으로. 직원이 '아직이에요'를 눌러 넘어간 경우 답 문구는 "해결이 안 돼서 점장님께 넘겼어요. 급하면 직접 불러 주세요."로 바꾼다.
3. **점장 답 → 카드 제목**: 규칙 모드에서 카드 제목을 질문 원문 대신 점장 답의 첫 문장(40자 이내)으로, situation은 질문 원문으로. 점장이 쓴 답은 지금처럼 바로 승인 카드다(점장 본인 작성).
4. **승인 카드 고치기**: `POST /api/stores/:id/cards/:cid/edit` body `{ edits, editorId }`. 편집자가 그 매장 점장이면 승인 상태 유지, 아니면 pending으로 돌린다(승인 뒤 고치면 다시 승인).
5. **첫 근무 준비 필수 상황**: 법·안전 상황 T06(신분증)·T10(취객·계산 분쟁)은 카드가 있으면 순위와 관계없이 항상 포함한다. 나머지를 priority 순으로 채워 최대 8장, 목록 순서는 priority 순. 필수 상황의 why는 storeReviews < 3이면 "법·안전 문제라 꼭 먼저 읽어요".
6. `StoreState.now`: db.today()와 서버 현재 시각을 Question.time과 같은 형식으로.

### 8.2 직원 화면

1. **홈 순서**: (a) 상황 버튼 가로 스크롤 1줄 → (b) 입력창 + 바로 아래 붙은 보내기 버튼(Enter 보내기, Shift+Enter 줄바꿈) → (c) 답(도착하면 scrollIntoView) → (d) **내 질문**(내가 물은 질문 최근 순: 대기 중 / 답 옴. 답 온 것은 점장 답 + 새 카드 칩) → (e) 신입 준비 띠 → (f) 오늘 브리핑 3개(나머지는 `<details>` 접기).
2. **답 모양**: 맨 위 "손님께 이렇게 말하세요"(카드 customerNotice, 말풍선, 그대로 읽을 문장) → "이렇게 해요" actions 앞 2줄 → "더 보기"(왜, 하지 말 것, 점장 부를 때) → 근거 카드 칩은 맨 끝 한 번. 직원 화면에서는 RunProgress·runId·'에이전트 n명' 숨김. 넘김이면 nearCardId 카드의 대사·행동 2줄을 "지금 할 수 있는 것"으로 보여 주고 "점장님을 직접 불러 주세요"를 굵게.
3. **알림 점**: 내 질문 중 답 온 것을 아직 안 봤으면 하단 탭·사이드바 '홈'에 점. 본 것은 localStorage(사람별)로 기억.
4. **'나'**: localStorage에 저장. 저장된 값이 없으면 첫 진입 때 한 번 "누구세요?" 선택(직원 이름 버튼). 바꾸면 화면 상태 초기화(`key={me}`). 매장명 카드는 없애고 '나'는 홈 맨 위 한 줄로.
5. **상단바**: 직원 역할에서는 'AI 모드'·'실시간'·'심사 모드' 칩을 숨기고 '가상 포함' 표지만 작게 남긴다.
6. **첫 근무 준비**: 한 장씩. 위에 진행 막대 + 장 번호, 카드 1장, 아래 '읽었어요'(다음 장으로 이동)·'이전'. 읽은 장 목록은 아래 접힌 한 줄들. 인용은 단어 경계에서 자르고 …(백엔드가 120자+…로 준다).

### 8.3 점장 화면

1. **넘어온 질문**: '지금 바로'(30분 이내, now 기준) / '오늘 안에'로 묶고, 각 질문에 'n분 전'. 지금 바로 묶음은 펼침, 나머지는 접힘.
2. **점장 답 저장 후**: 만들어진 카드를 그 자리에서 미리 보여 주고 '고치기'(카드 edit API).
3. **승인 대기 카드**: 승인 버튼 위에 확인 3개(우리 매장 사실이 맞아요 / 금지 표현이 없어요 / 신입이 읽고 바로 할 수 있어요). 셋 다 체크해야 승인 버튼이 켜진다.
4. **오늘 할 일 줄**의 숫자를 누르면 해당 패널로 스크롤. 하단 탭·사이드바 '오늘 할 일'에 넘어온 질문 수 배지.
5. **상황 표**: 카드 없는 상황만 먼저, 나머지는 "카드 있는 상황 n개 더 보기". 배지 문구 "매장 카드 없음 · 본사 카드만". 새 알바 준비 상태는 이름·막대·k/N 한 줄씩, 안 읽은 목록은 접기.
6. 용어: 위키 점검의 'LINT' 부제 → 'CHECK', 'RD001' 같은 번호는 숨김(내부 id는 title 속성으로만). 점장 메뉴의 '지식 그래프'는 사이드바에만 두고 하단 탭에서는 뺀다.

### 8.4 하지 않는 것

실제 푸시 알림이 있는 척하는 문구, 개인별 질문 수·평가 숫자, 퀴즈·점수, 본사 화면 대개편(P2는 이번 범위 밖).
