# 윤슬 HQ 화면 개편 브리프 (v2)

v1 화면을 다음 결정에 맞게 고친다. `docs/DESIGN.md`는 이 브리프대로 다시 쓴다.

## 결정 사항 (사용자 확정)

1. **전부 웹, 반응형.** 본사 SV·점장·알바가 같은 웹 셸을 쓴다. 휴대폰 프레임이나 '앱' 표현은 쓰지 않는다. 알바 화면도 같은 상단바·내비 구조 안에서 반응형으로 보인다(좁은 화면에서는 하단 탭, 넓은 화면에서는 사이드바).
2. **역전할머니맥주 브랜드 색·폰트를 쓴다.** 로고·캐릭터 이미지는 넣지 않는다. 로고 자리는 글자 워드마크 「역전할머니맥주 × 윤슬」.
3. 브랜드는 실명, 매장은 익명. 가상 표준·가상 시나리오 표지는 유지한다.

## 색의 뜻 (한 색 한 뜻)

- **brand-red #E60012 = '고위험'과 워드마크.** 고위험 배지·고위험 매장 행 왼쪽 4px 바·KPI 고위험 숫자에만 쓴다. 버튼·활성 메뉴에는 쓰지 않는다(사회보장 레드 예산 규칙: 화면 면적 5% 이하).
- **brand-ink #231815 = 주 버튼·활성 메뉴·제목.** 
- **brand-yellow #FCC800 / highlight #FDD84C = 강조와 '주의'.** 주의 단계(위험 30~59), 리뷰 인용 속 근거 문장 형광펜 밑줄, 선택된 탭 밑줄, 브리핑의 '손님께 할 말' 말풍선 배경(#FFF4C2 같은 옅은 노랑).
- **배경:** 따뜻한 미색 #FFF8F5(char-pink를 아주 옅게) + 카드 흰색, 선 #EFE3DE. 상단바는 brand-ink 바탕 + 흰 글씨(사이트 헤더처럼 단단한 인상).
- **원인 4분류:** 브랜드 톤에 맞춰 다시 고른다(색약 구분 유지, 빨강·노랑과 겹치지 않게). 예: 지식 공백 #1F5FA8(파랑), 운영·인력 #7E2A1E(체크셔츠 갈색), 매장 자체 규칙 #6B6115(올리브), 위생·품질 #0B6E78(청록). 항상 아이콘+글자와 함께.
- 차트: 카카오 = brand-ink, 네이버 = #9C8F89(따뜻한 회색), 강조 막대만 노랑.

## 톤과 장식

- 사이트처럼 짧고 단단한 문장. 제목은 Gmarket Sans Bold, 한글 제목 아래 작은 영문 보조 문구를 붙일 수 있다(예: 「전국 현황 · OVERVIEW」).
- 강조어 밑에 노랑 형광펜 밑줄(사이트 `.highlight_line` 재현)을 한 화면에 한두 번만.
- 말풍선 모양(사이트 `border-radius: 33px 0 33px 33px`)을 브리핑의 '손님께 할 말'과 빈 상태 안내에 쓴다.
- 이모지·보라 그라데이션·뇌/로봇 아이콘·"AI가 분석했어요" 금지. lucide 선 아이콘만.

## 셸 (세 역할 공통)

- 상단바(brand-ink): 워드마크 「역전할머니맥주 × 윤슬」 · 역할 전환(본사 SV / 점장 / 직원) · 매장 표시 · AI 모드 · 가상 표지 · 실시간 연결.
- 왼쪽 사이드바 240px(≥1024): 역할별 메뉴 그룹. <1024: 사이드바가 숨고 하단 탭바(최대 5칸, 44px 이상 터치).
- 본문 최대 1280px, 12열. 직원 화면도 같은 셸이며, 본문 폭만 640px로 좁힌다(앱 흉내 금지).
- 실행 중이면 사이드바 '에이전트' 메뉴 옆에 점(이벤트가 있을 때만).

## 화면별 보강 (과거 프로젝트에서 옮길 것)

**본사 · 전국 현황**: 맨 위 한 줄 경보 띠(금융 UrgentCallout: 고위험 매장 수 + 바로가기 1개) → KPI 6개(masdae KpiCards: 로딩 '…', 없음 '—', 하단 노랑 선) → 위험 순위 표(사회보장 Queue: URL 필터·aria-sort·고위험 행 왼쪽 빨강 바, md 미만은 카드 목록) → 평점 분포·원인별 집계·히트맵·지역 요약. 표 안 위험 막대는 ScoreBar 형식(숫자 + 64×8 막대).

**본사 · 매장 상세**: 본문 + 오른쪽 360px sticky '결정 패널'(사회보장 DecisionPanel: 진단 실행 · 처방 만들기 · 보낸 처방 상태 · 4주 가상 결과 버튼). 진단 결과 인용 문장은 원문 속 해당 구절을 형광펜(<mark>)으로 표시하고, 누르면 오른쪽 서랍(masdae ClaimDrawer 틀 + 관광공사 포커스 트랩)에 리뷰 원문 전체를 연다. 점수 R1~R5는 근거 문장 칩과 함께.

**본사 · 에이전트 운영**: masdae agent-team 구성으로 다시 만든다. FlowRail(지휘 → 관측 → 진단 → 처방 → 검증) + 팀 열 × 에이전트 카드(상태 pill, 요약 3줄, via·ms·막힘 수, 실행 중이면 상단 shimmer) + GatePanel + 단계 상세 서랍. 진행 중 단계는 'N초 경과'(금융 useNow), 끝나면 로그 접기. 이벤트 없이 움직이는 애니메이션 금지, prefers-reduced-motion 정지. 팀 구조 보기(금융 TeamStructureView: 게이트를 띠로 그림 + 오른쪽 인스펙터)를 탭으로 함께 둔다.

**점장**: 같은 셸. 첫 화면 위에 '오늘 할 일' 한 줄(승인 대기 n · 넘어온 질문 n · 점검 n), 그 아래 우리 매장 진단 요약 → 받은 처방(본사가 보낸 것) → 승인 대기 카드(카드 상세 dl 구조) → 넘어온 질문 답하기 → 위키 점검.

**직원**: 같은 셸, 좁은 본문. 메뉴: 오늘 브리핑 / 물어보기 / 기록하기 / 매장 위키. 브리핑은 말풍선 카드('손님께 할 말')와 '왜'. 물어보기는 답 + 근거 카드 칩([C015] 누르면 카드 펼침, 관광공사 useEvidenceDrawer) + 에이전트 한 줄 진행(관광공사 agent-work-line, 끝나면 접힘). 주요 버튼 52px.
